## 4. 중복 제거 재검증

분류 기준(현재 코드): ① `strategy_id` = 정규화한 정의의 해시(키 순서·기본값·교환 가능한 조건 순서·`_note` 무시),
② `behaviour_key` = 정확히 같은 거래를 하는 정의(진입/필터 같은 조건, 같은 특성의 구간 합치기, 정수 특성 경계, 위험
설정 — 어떤 평가 단계도 읽지 않음), ③ `near_duplicate` = 구조가 같고 임계값 차이가 변이 한 걸음의 절반 미만(유지하되
검증 배치에는 그룹당 하나). 보유 기간·손절은 ②의 일부라 다르면 다른 전략이다.

R6 보고서의 "행동 중복 30, 정의 중복 15"는 **거절 결정 횟수**다. 서로 다른 정의로 세면 24 / 12다(같은 정의가 여러 라운드에서
다시 제안되어 다시 거절됨). 재실행에서도 30/15, 24/12로 같다. 임계값은 바꾸지 않았다.

추가한 테스트(7가지): 정의 동일 / 이름만 다름(`_note`) / 작은 매개변수 차이로 행동 동일(정수 경계는 정의상 동일, 절대 묶이지
않는 필터 임계값 차이는 near로 표시되고 실제 거래가 완전히 같음) / 보유 기간·손절이 달라 행동도 다름(진입이 같아도 묶지 않음) /
같은 계보에서 반복 생성(대표 id와 함께 거절) / 기존 후보와 진화 후보 사이 중복 / 경계(절반 걸음 −1e-6은 near, 정확히 절반은 아님,
창 길이 96 vs 97은 구조가 달라 near 아님).

**실데이터 진단(R6 재실행 DEV 통과 64개):** DEV 거래가 완전히 같은 쌍이 1개(`S-3f825ccdd41fb32d`, `S-bdae1ff0b24876cc`) →
서로 다른 행동 63개. 진입 Jaccard가 0.99 이상인 쌍이 여럿이고 그 쌍들은 모두 청산이 다르다(보유 기간·손절 차이). 즉
상위 후보 다수는 **같은 진입 신호에 청산만 다른 변형**이다. 규칙대로 합치지 않았고, 검증 배치에서 하나로 줄일지는 사용자 결정이다.

## 5. 비용 모델의 가정과 한계, 민감도

가정(바뀌지 않음): 한쪽 비용 = 수수료 + 반 스프레드 + 충격계수 × √(주문/봉 거래대금), 참여율 상한 초과 주문은 거부(가격을
매기지 않음), 진입·청산 모두 테이커, 수수료 등급·리베이트·BNB 할인 없음, 손절은 손절가에 체결(갭이면 시가). 비용 누락·0 거래대금은
`CostDataMissing`, 설정 누락은 `CostConfigError` — 낙관적 기본값으로 대체하지 않는다. 모든 DEV 기록에 비용 버전·상태가, 실험 맥락에
파라미터가 남는다. 이전의 20만 건 교차 검사는 **구현 일치**만 보여 줄 뿐 실제 시장 비용의 정확성은 아니다.

R6 재실행의 비용 상태는 `ESTIMATED_FROM_PUBLIC_DATA`(공개 호가 추정, 수수료는 가정). **실제 체결 관측값이 아니다.**
실제 체결 보정(`fills_import.py` → `cost_calibration.py`)은 사용자 본인 계정의 체결 내역 종목당 200건 이상이 필요하며 지금은 없다.
실계정 연결은 구현하지 않았다.

민감도(첫 10개 검증 후보, DEV 구간만, 거래당 순수익 bp): 기준 24.9~97.3 → 수수료 ×2에서 정확히 10bp 감소, 모든 구성요소 ×2에서
10.9~83.3. 10개 모두 시험한 시나리오 안에서는 0 이하로 내려가지 않았고 단조성 위반은 없다. 주문 ×25에서 거부 0~2건. **진입 변동성이
중앙값 아래인 거래는 10개 중 9개가 기준 비용에서도 음수**(−0.1~−30.4bp)이고 수익은 고변동성 구간에서만 나온다. 이 DEV 수치는
선택에 쓰인 구간이므로 증거가 아니다.

## 8. 통계 기준 유지

- 바꾼 기준 없음. `promotion_v3.json`, `independent_window_v1.json`, `cost_assumed_public_v1.json`, `cost_verification_v1.json`의

  안에서 Romano-Wolf StepM(FWER), 배치 간 1/k² 알파 소비(검색 전체 0.05를 두 창에 나눔), BH/BY는 진단만. IW1은 묶음 간 소비 +
  StepM. **894개 탐색 전체의 선택 편향은 검정으로 보정되지 않는다.** 보호 장치는 선택과 분리된 새 데이터뿐이며, BTC/ETH 검증 창은
  이미 7회 사용되어(이력 전체 FWER 상한 약 0.096) 새 증거가 될 수 없다.
- 누출: DEV/검증/잠금 분리(`split_windows`, 엠바고 96봉), 특성 인과성 테스트, 검색은 DEV 피드백만 읽음(`FeedbackLeak`). 이번에
  바꾸지 않았고 기존 테스트가 통과한다.
- 비용 전후: DEV 기록에 gross/cost/funding/net 분리. 검정력 부족은 `INCONCLUSIVE`(=UNDETERMINED_POWER)로 남고 성공·실패로 분류하지 않는다.
