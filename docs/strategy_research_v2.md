# NEW2 전략 리서치 v2 — ADR 전수 재확인 + 겹침 없는 신규 후보

**작성일:** 2026-10-11 (사용자 현지 시간 기준)
**대상 저장소:** github.com/tlsehd195/NEW2, `main` HEAD `5facae8` (이전 감사 기준 `3e5c9cd` 대비 **57개 신규 커밋**)
**이 문서의 성격:** Claude Code에 전달하여 실행할 수 있는 지시문. 이전 리서치(`전략리서치_보고서.md`)의 S1/S2 필드테스트 결과와 그 이후 저장소에 새로 쌓인 ADR-0064~0079까지를 **전부 반영**하여, 이미 시도되거나 기각된 것과 **겹치지 않는** 후보만 담는다.

## 0. 가장 중요한 결론 3줄

1. **S3(레짐 전환)는 이미 테스트되어 기각됐다.** Claude Code가 "S3를 테스트할지" 물었지만, 저장소의 ADR-0079(2026-10-10)에서 이미 규칙을 고정해 선별까지 완료했고 결과는 BTC·ETH 모두 베이스라인보다 나빴다(거래 수 약 2배 → 비용 손실만 증가). **S3에 예산을 쓰지 말 것. 회신은 "ADR-0079에서 이미 기각됨" 한 줄이면 충분하다.**
2. **P5/P7 h48을 결선에 올리지 말 것.** ADR-0070의 유일한 양수 후보지만 DSR 0.12~0.18로 기준 0.95에 한참 못 미치고, ADR-0070 스스로 "거래 횟수 감소 효과일 수 있다"고 명시했다. 2026-10-29 이후 풀리는 등록 예산 3칸을 이것으로 소진하는 것은 기대값이 음수다.
3. **가장 큰 기회는 새 신호가 아니라 비용 구조다.** ADR-0065는 결론에서 스스로 "다음 후보는 비용 구조가 다른 쪽(지정가 수수료 환급형 진입)이지만 사용자 결정이 필요하다"고 적어뒀다. 왕복 12~20bp 테이커 비용이 지금까지의 모든 방향성 후보를 죽였다. 지정가 진입으로 비용 바닥을 6~10bp로 낮추면, 이미 측정된 최상위 후보(S2 BTC 12h 총 +35bp 등)가 재평가된다.

## 3. 신규 후보 (겹침 없음 검증 완료, 우선순위 순)

### N1. crowd-positioning 비율: Binance metrics 아카이브의 미사용 4개 컬럼 ★최우선

**무엇인가**
- `data.binance.vision/data/futures/um/daily/metrics/<SYMBOL>/` 파일에는 5분 간격으로 다음 컬럼이 있다:
  - `count_toptrader_long_short_ratio` (상위 트레이더 **계좌 수** 롱/숏 비율)
  - `sum_toptrader_long_short_ratio` (상위 트레이더 **포지션 규모** 롱/숏 비율)
  - `count_long_short_ratio` (전체 계좌 롱/숏 비율)
  - `sum_taker_long_short_vol_ratio` (테이커 매수/매도 물량 비율)
- 저장소의 파서(`binance_vision.py` METRICS_COLUMNS)는 **`sum_open_interest` 2개 컬럼만 읽고 나머지 4개는 한 번도 로드·테스트한 적이 없다.** ADR-0070의 `oi_dir/oi_chg`는 OI **총량** 변화였고, 이 후보는 **참여자 방향 쏠림(비율)** 이라 별개 정보다. 펀딩비(가격 조정 변수)와도 기제가 다르다(S4와 다른 계열).

**실측 검증 완료 (본 문서 작성자가 직접 확인)**
- 스키마: `BTCUSDT-metrics-2024-01-15.zip` 다운로드 → 8개 컬럼 존재 확인 (위 표 그대로)
- 가용 기간: BTCUSDT **2021-05-01부터** (HTTP 200 확인), ETHUSDT 2021-12-01부터 (2021-11-01은 404)
- 미잠금 구간과의 교집합:
  - BTC: **2021-05~2022-08-16** (≈15.5개월) + **2023-04-06~2024-03-24** (≈11.5개월) — 서로 다른 두 레짐
  - ETH: **2024-12-01~2026-04-27** (≈17개월)
- 데이터 무료, 일 1파일 ~0.1MB 수준, 기존 `BinanceVisionMetrics` 로더에 컬럼만 추가하면 됨.

**왜 비용을 넘을 가능성이 있나 (정직한 평가)**
- 근거 등급: **C+~B (실무자 등급)**. 학술 논문은 드물지만, COT(전통 선물 포지셔닝) 역발상 연구 계열과 크립토 실무계(crowd L/S ratio 극단값 역발상)에서 널리 쓰이는 접근이다. "약세 근거"라서 등록 예산을 쓰기 전 Phase A 측정(저장소 표준 절차)에 정확히 맞는 형태다.
- 기제: 개인 투자자 계좌 롱 쏠림 극단 → 단기 반대 방향(청산 압력). OI·펀딩·호가·가격 지표 어디에도 없는 **참여자 구성** 정보.

**Phase A 설계 (ADR-0076 방식 그대로)**
- 점수: 각 비율의 96봉(24h)·960봉(5d) 백분위, 인과적 expanding z. 신호는 |z|≥1 상위 분위(q80/q90/q95).
- 방향 규약: 역발상(계좌 롱 쏠림 극단 → 숏)과 순발상 둘 다 측정해 보고(사전 고정).
- 지평: 4/16/48봉(1h/4h/12h). 구간: 위 미잠금 3개. 분기별 부호 안정성, 비용 12/16/20bp 대비, base-rate Brier 비교까지 `diagnose_signal_candidates.py`에 metrics 입력만 추가.
- 다중검정: 3비율×2규약×3지평×3구간을 한 가족으로 Holm. 사전 고정, 결과 후 조정 금지.
- **등록·예산 0 사용.** 유의하면 그때 새 id로 결선 검토.

**위험**
- 5분 데이터를 15분봉으로 집계하는 과정에서 미래 누출 주의(봉 마감 기준 인과 집계 — 기존 로더 규약 준수).
- 학술 근거 약함 → Phase A에서 비용 미달이면 즉시 폐기하고 다음 후보로.

### N2. 지정가(maker) 진입 실행 전환 — 비용 바닥 12~20bp → 6~10bp ★최대 기대효과 (사용자 결정 필요)

**무엇인가**
- 지금까지의 모든 측정은 왕복 테이커 비용 12~20bp를 전제한다(왕복 수수료 10bp + 스프레드/임팩트). 바이낸스 선물 VIP0 기준 메이커 2.0bp/테이커 5.0bp, BNB 결제 시 1.8/4.5bp.
- **진입만** 포스트온리 지정가로 바꾸고 청산은 시장가로 남기면 왕복 비용이 약 6~10bp로 내려간다(진입 메이커 2bp + 스프레드 절반 + 청산 테이커 5bp + 임팩트).
- ADR-0065 결론이 직접 명시한 "다음 후보는 비용 구조가 다른 쪽(지정가 수수료 환급형 진입)이지만 15분 단타 규칙과 어긋나 사용자 결정이 필요하다"를 실행하는 것이다.

**왜 신규 전략 연구에 포함하나**
- 신호가 아니라 **인프라/실행 계층** 변경이므로 어떤 기각 항목과도 겹치지 않는다. 그리고 그 자체가 "비용 미달" 판정을 뒤집는 레버다:
  - S2(BTC 12h) 총 +35bp → 순 +27bp 전후 (비용 8bp 가정) — 단, ETH 미재현 리스크는 그대로라 재선별 필수
  - ADR-0065 ETH 되돌림 16봉 총 +11.6bp → 순 +3~5bp — 여전히 약함
  - ADR-0066 5분봉 투표 12h +13~26bp → 순 +5~18bp — 반기별 부호 뒤집힘 여전
- 요점: **메이커 전환은 후보를 살리는 만능이 아니라, "비용 미달" 판정들을 정확한 기준으로 다시 재심사하는 것.** 재판정 후에도 살아남는 것이 있는지가 질문이다.

**구현 과제 (정직한 난이도 평가)**
1. 체결 모델: 지정가 진입은 "체결 안 될 확률"과 "체결됐다면 adverse selection"이 있다. 정직한 방법은 보수적 규칙 — 지정가를 당시 최우선 반대호가에 걸고, **그 가격이 aggTrade로 실제 거래통과(trade-through)됐을 때만 체결로 인정** + 체결 지연 시 신호 만료 처리. bookDepth(30초)로는 큐 위치 모델링 불가 → aggTrade 필요(아카이브 존재, ADR-0076 확인).
2. `paper/engine.py`와 백테스트 `event_engine.py`에 지정가 주문 경로 추가(현재는 깊이 걷는 시장가만).
3. 미체결 리스크: 진입 실패율을 별도 지표로 보고(못 들어간 구간이 "살아남은 엣지"의 대부분일 수 있음).
4. **사용자 결정 항목:** 15분 단타 규칙(ADR-0031)은 진입 방식을 제한하지 않으므로 규칙 위반이 아니지만, "진입 대기 중 청산 쪽 이탈" 처리 방식과 모의투자 재시작이 필요하다.

**순서:** 백테스트 실행 계층에 지정가 경로 → 동일 데이터로 기존 최상위 후보 재판정 → 살아남으면 그때 선별 등록. 예산 0(등록 전까지).

### N3. 김치 프리미엄 (업비트 KRW-BTC vs 바이낸스 USDT ×환율) — 교차거래소 프리미엄 신규 정보원

**무엇인가**
- 김치프리미엄 = (업비트 KRW-BTC 가격) ÷ (바이낸스 BTCUSDT × KRW/USDT 환율) − 1.
- 한국 자금 유입 압력의 직접 측정치. CryptoQuant 가이드 기준 "김치 프리미엄 ≥16%는 역사적으로 단기 고점/과열(FOMO) 지표" — 즉 **역발상 센티먼트 극단값** 관행이 확립돼 있다. 한국 학술 문헌(환율 연동 통계차익거래 연구 등)도 존재.
- 저장소에 없는 **교차거래소 프리미엄** 정보원이며, 자금 흐름 규모가 실제로 다른(원화 시장) 정보라 국내 거래소 프리미엄 관련 어떤 기각 항목과도 겹치지 않는다.

**저장소 내 데이터 파이프 상태 (확인 완료)**
- `data/upbit_rest.py` `UpbitRestCandles`는 범용 — `market="KRW-BTC"` 즉시 지원(모듈 docstring에 KRW-BTC 언급).
- 환율: `accounting/krw_rates.py`가 업비트 KRW-USDT 15분 종가 수집기 이미 구현·운용 중.
- 제약: 업비트 API는 클라우드/Actions에서 403(ADR-0040) → **수집은 사용자 PC에서만**. 과거 백필: 업비트 분봉 REST는 수년 전까지 제공(2017~18년부터). 백필 스크립트 1회 실행 + 이후 15분마다 증분 수집(기존 collect_krw_rates.py 패턴 복제).

**Phase A 설계**
- 점수: 프리미엄의 96봉/960봉 백분위 + 절대 프리미엄 구간(예: ≥5%, ≥10%, ≥16%).
- 방향: 극단 고프리미엄 → 역발상(숏). 4/16/48봉. BTC만(한국 거래소 대표).
- 유의점: 프리미엄 시계열은 환율 변동과 상쇄되므로 반드시 환율 보정 후 측정. 업비트 15분봉 결손 처리(저유동 시간대) — 기존 gap 보고 규약 준수.
- **등록·예산 0.** 데이터 백필이 사용자 PC 작업이라는 점만 제외하면 N1과 동일한 저비용 진단.

**위험**
- 15분~12h 지평에서 예측력이 있다는 학술 검증은 아직 없음 (관행적 사용 근거만). → 어디까지나 Phase A.
- 백필 기간이 길어 사용자 PC에서 수 시간 소요 가능.

### N4. 크로스섹션 단기 되돌림 (15분봉 유니버스, 룩백 4~24h, 보유 ≤12h) — 차순위

**무엇인가**
- XS 계열에서 모멘텀은 H-0017/0018로 죽었지만 **되돌림은 한 번도 테스트되지 않았다.** ADR-0017의 결론도 "다음 시도는 사전에 다른 질문으로 새로 등록해야 한다"고 명시 — 되돌림은 정확히 "다른 질문"이다.
- 문헌: 크립토 크로스섹션에서 7일/30일 되돌림 팩터가 유의하다는 실증(Grobys 등의 momentum-reversal 연구, 일별 예측력 연구에서 "7·30일 reversal이 가장 유의한 밸류에이션 팩터" 보고). 단, 문헌은 일간~주간 정렬이 많고 15분봉 지평 근거는 약하다 — 이 갭을 정직하게 명시.

**저장소 제약과의 충돌 점검**
- "일봉 스윙은 더 하지 않음"(ADR-0030) → 15분봉 기반 + 보유 ≤12h로 설계하면 daytrade 규칙 내.
- XS 엔진(`xs` 계열)과 코인 유니버스 규칙(밈코인 제외)은 기존 코드 재사용.
- 비용: 진입+청산 2다리, 리밸런스 턴오버 큼 → **1차 필터로 "비용 차감 후 기대"를 먼저 계산**해야 함(ADR-0065 스타일). 예상: 15분 지평에서는 비용 문제로 어려울 가능성이 높다. 그래서 4순위.

**위험**
- H-0017/0018에서 같은 유니버스에 락이 걸린 구간(2022-08-17~2023-04-06, TEST-18 구간) 회피 필요 — 유니버스 후보 코인의 미잠금 구간을 별도 확인해야 함.
- XS 주간 실행이 아닌 15분 실행이라 기존 XS 엔진 수정 필요.

**권고:** N1/N2가 모두 실패할 때만 Phase A로 올릴 것.

## 5. 실행 순서 (Claude Code 지시서)

> 전제: 예산 2026-10-29 11:32 KST까지 가득 → 그 전에는 등록 0, 진단·선별만. 모든 측정은 잠금·예약 구간 회피(스크립트가 이미 거부함). 각 단계 결과는 새 ADR로 기록.

- **R1. metrics 로더 확장** — `BinanceVisionMetrics`에 4개 비율 컬럼 추가(파서 fail-closed 규약 유지). 테스트: 실제 아카이브 파일 1개로 파싱 검증.
- **R2. N1 Phase A** — `diagnose_signal_candidates.py`에 metrics 점수 입력 추가, 구간 3개(BTC×2 era + ETH)에서 측정. Holm 가족 사전 고정. 산출: 각 비율의 corr·q80/q90/q95 총이동(bp)·분기 부호·Brier.

- **R4. N2 지정가 실행 계층** — 백테스트 엔진에 포스트온리 진입 경로(보수적 trade-through 체결 규칙) + 진입 실패율 지표. 사용자 PC 모의투자에는 적용하지 말고 백테스트 전용으로 먼저.
- **R5. N2 재판정** — 기존 최상위 후보(S2 BTC 12h, ADR-0066 5분 투표 12h, ADR-0065 ETH 되돌림 16봉)를 메이커 비용 구조로 재계산. **순수익이 비용 0선을 넘는 후보가 생기면** 새 id로 선별 등록. (S2는 ETH 미재현 문제로 등록 최소 조건: ETH 구간에서 같은 방향 단서 확인)
- **R6. N3 데이터 백필 (사용자 PC)** — `collect_krw_rates.py` 패턴 복제해 KRW-BTC 15분봉 백필+증분 수집 스크립트 실행. 완료되면 클라우드가 CSV를 읽어 N3 Phase A(환율 보정 프리미엄 점수) 진행.
- **R7. 결선 예산 사용 (2026-10-29 이후)** — 위에서 선별을 통과한 후보 중 최강자만 등록(예산 3 중 1~2칸). P5/P7은 등록하지 않음.
- **병렬 작업 (전략 무관, 남은 미해결):** `verify_markets.py --write` 사용자 PC 실행, 첫 실제 모의투자 후 `check_ws_quality.py`로 `decisions > 0` 확인 — 이 두 건은 이전 보고서 T6/T7의 유일하게 남은 항목.
