## 2. 전략 후보 6종 (연구 근거 + 프로그램 접목 방법)

### 🥇 S1. "15분(Quarter-Hour) 효과" 오더 불균형 투표 — 최우선

- **근거**: Kim & Hansen (2026), *The Quarter-Hour Effect: Periodic Algorithmic Trading and Return Predictability in Cryptocurrency Futures*, arXiv:2607.09426
  - URL: https://arxiv.org/abs/2607.09426
- **핵심 발견** (바이낸스 퍼페추얼 6종 실측):
  1. 15분 경계(quarter-hour marks)에서 변동성·거래량이 주기적으로 폭발 — 알고리즘 참여 때문
  2. **15분 시작(opening) 수익률이 out-of-sample로 예측 가능**
  3. **15분 시작 시점의 오더북 불균형(order imbalance)이 4~12시간 수익률을 예측** — 더 촘촘한 주기(1분·5분)에서는 효과가 약함
- **프로그램 적합성**: 15분봉 시스템 / h16(4h)·h48(12h) 예측 지평 / 최대 12시간 보유와 **정확히 일치**. 5분봉 미사용 결정(ADR-0030)과도 일치.
- **접목 방법**: V2의 이미 구현된 피처를 7번째 투표로 연결.
  - `BookTicker`/`TradeTick` 스트림은 이미 구독 중 → 새 데이터 피드 불필요
  - 15분봉 열림 시점 기준 최근 N분(예: 5분)의 `ticker_imbalance` + `trade_imbalance`(=`TradeFlowWindow`)를 집계해 `order_imbalance` 투표 신설
  - 단, **BUG-2(페이퍼 엔진이 DepthDelta를 버림)를 먼저 수정**해야 북 데이터가 완전해짐 — 이전 보고서(`NEW2_분석보고서.md`) T2 참조
- **사전 진단**(등록 전, 예산 소모 없음): `scripts/diagnose_vote_frequency.py` / `scripts/calibrate_vote.py`로 신호 빈도·보정 확인 (수익은 읽지 않는 정당한 탐색 경로)
- **리스크**: 논문 효과는 시간이 지나면 약해질 수 있음(arbitrage decay). 효과 크기가 거래비용(테이커 수수료+스프레드)보다 큰지 진단 단계에서 반드시 확인.

### 🥈 S2. 인트라데이 타임시리즈 모멘텀 (TSM) 투표

- **근거**: Shen et al. (2021-22), *Bitcoin intraday time-series momentum* (Univ. of Birmingham CentAUR, 피인용 52)
- **핵심 발견**: 당일 이미 지난 시간대의 누적 수익률이 이후 수익률을 예측. **거래비용 반영 후에도 수익 유지**가 확인된 몇 안 되는 인트라데이 전략.
- **접목 방법**: `daytrade_intraday_tsm` 투표 신설 — UTC 자정부터 현재 마감 봉까지의 누적 수익률 부호/크기를 투표 점수로 사용. 구현은 `raw_scores()`에 함수 하나 추가 수준.
- **⚠️ 이름 주의 (V6)**: 후보 id에 `ts_momentum_*` 글롭을 쓰면 등록 거부됨. 반드시 `daytrade_tsm_*` 계열로 명명. `hypothesis_rationale.jsonl`에 "데일리 TSM(H-0002~H-0010)과의 차이: 시간단위 15분, 하루 내 청산, 결정 시점 상이"를 40자 이상 기록할 것.
- **리스크**: 데일리 버전이 좌초했던 이유(비용·비일관성)가 인트라데이에선 다를 수 있지만, 보장은 없음 → 진단 먼저.

### 🥉 S3. 레짐 조건부 투표 전환 (모멘텀↔반전 스위치)

- **근거**: Wen, Bouri, Xu, Zhao (2022), *Intraday Return Predictability in the Cryptocurrency Markets: Momentum, Reversal, or Both* (Finance Research Letters, 피인용 51)
  - BTC 2013-2020 고주파 데이터 + ETH/LTC/XRP에서 재확인
- **핵심 발견**:
  1. 인트라데이에서 **모멘텀과 반전이 동시에 존재**하며 조건에 따라 지배적인 쪽이 바뀜 (점프 발생 여부, 유동성 수준, 구조 변화)
  2. **반전은 암호화폐 고유 특성** (비기본적 정보 과잉반응 + 과신 편향)
  3. 이 예측변수로 만든 타이밍 전략이 always-long/buy-and-hold 대비 경제적 가치 우위
- **프로그램 진단 매칭**: ADR-0042(BTC 보정 실패)의 원인 설명 — 고정 가중치 투표는 레짐별로 부호가 뒤집히는 신호를 평균내어 무력화함.
- **접목 방법**: 기존 6투표 패널 유지 + `classify_regime()` 결과에 따라 투표 부호/가중치를 전환하는 래퍼. 예: `HIGH_VOL`에서는 반전 방향(ROC·RSI 반대), `TREND`에서는 모멘텀 방향. 레짐 분류기는 이미 구현돼 있어 신규 피처 불필요.
- **리스크**: 레짐 전환 규칙 자체가 과최적화 지점이 될 수 있음 → 전환 규칙을 사전등록문에 명시하고 2가지 이상 변형으로 제한.

### S4. 펀딩비 극단값 역추세 (크로스섹셔널) 투표

- **근거**:
  - Presto Research (2024.8), *Can Funding Rate Predict Price Change?* (Jin H. Jung) — URL: https://www.prestolabs.io/research/can-funding-rate-predict-price-change
  - Helminen (2022, Aalto Univ.): 펀딩비→ETH 가격 Granger 인과성 확인
- **핵심 발견**:
  1. 펀딩비 변화가 7일 가격 변동의 12.5% 설명, 이후 기간엔 급감 → **단일 자산 방향 예측은 약함**
  2. **크로스섹셔널(복수 코인 비교)로 쓸 때 더 유용** ← Presto 결론
- **접목 방법**:
  1. `BinanceFundingRateHistory`(V5)로 4종(BTC/ETH/SOL/XRP) 펀딩 히스토리 수집 → 페이퍼 트레이더에 주기 갱신 스레드 추가
  2. `funding_crowding_score`(V4)를 투표로 승격: 극단 양수 펀딩(롱 과밀) → 숏 가중 / 극단 음수 → 롱 가중
  3. 크로스섹셔널 버전: 4종 중 펀딩 상대 순위를 보조 신호로
- **리스크**: 펀딩은 8시간 주기(일부 4h)라 15분봉 투표와 시간 스케일 불일치 — "직전 펀딩 확정치"만 사용(미래 펀딩 추정 금지, fail-closed 원칙). 죽은 계열 `funding_carry_*`는 캐리 수익 전략이고 이건 방향 신호지만, 등록문에 차이를 명확히 기록할 것.

### S5. 청산 캐스케이드 반전 투표 (작업량 최대, 후순위)

- **근거**: Chainlink/Amberdata/Blofin Academy 등 실무 연구 공통 패턴 — 강제청산 연쇄가 만든 긴 꼬리는 스탑 헌팅 후 즉각 반전 경향
- **핵심 발견**: 청산 폭발 1분 내 + wick > 3×ATR 조건에서 반전 진입이 실무에서 반복 관찰됨
- **접목 방법**: 바이낸스 `!forceOrder@arr` 스트림 신규 구독(V7: 현재 미구독) → `binance_ws.py`에 라우트 추가 → 1분 청산량 집계기 구현 → `liquidation_sweep` 투표 신설
- **리스크**: 스트림·집계기·백테스트 재현(과거 청산 데이터는 `binance_vision.py` CSV로 확보 가능)까지 3단계 작업. 등록 예산 관점에서 S1~S3 다음으로 미룰 것.

### S6. ATR 레짐 필터 돈치안 브레이크아웃 (저비용 변형, 참고용)

- **근거**: Poluri (2026, SSRN) 돈치안+ATR 레짐 필터 성과 평가 / QuantifiedStrategies.com 20개 백테스트 종합 결론 "암호화폐는 평균회귀보다 추세추종이 역사적으로 우위"
- **접목 방법**: `donchian_pos` 투표의 브레이크아웃 해석 변형 — 상단 돌파 + `classify_regime()==TREND`에서만 롱 가중. 구현 비용 최소.
- **리스크**: V1대로 기존 지표 재조합이라 **새 정보가 없음**. ADR-0046 지표 중복 진단 이력 고려 시 우선순위 낮음. S1~S3이 막히면 대안.

## 4. 추천 실행 순서 (등록 예산: 30일 3건, ADR-0031)

1. **진단 먼저** (예산 0 소모): S1/S2 신호의 빈도·보정을 `diagnose_vote_frequency.py`, `calibrate_vote.py`로 측정
2. **S1 등록·검증** (신규 정보원 + 근거 논문 최신 + 프로그램 적합도 최고)
3. **S3 등록·검증** (기존 인프라만으로 가능, ADR-0042 원인 직접 공략)
4. **S2 등록·검증** (구현 최저비용, 단 데일리 좌초 이력 설명 필요)
5. S4(펀딩 데이터 파이프 구축 후), S5(스트림 확장 후), S6(대안)

**현실적 기대치**: 논문들의 OOS 예측력은 약한 신호 수준이다. 이 프로젝트의 통과 기준(PBO≤0.2, DSR≥0.95)은 매우 엄격하고, 20개 가설이 전부 좌초한 것과 같은 맥락으로 상당수가 또 좌초할 수 있다. 그래도 정직하게 기록하는 것이 이 프로젝트의 방식이다.
