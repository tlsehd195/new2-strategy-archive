## §1. 검증 체계 (변경 없음 — 사전 고정)

1. **사전등록 선행**: 측정 스크립트 실행 전 `PREREG_*.md`에 셀 정의·임계값·Holm 규격·OOS 규칙을 고정. 사후 파라미터 재조정은 위반.
2. **Holm step-down 다중검정 보정**: 24셀 패밀리와이즈 α=0.05. 통과 셀 없으면 즉시 FAIL.
3. **엔진 비용 교차검증**: 저장소 `backtest/costs.py` CandleCostModel(fee+half_spread+sqrt impact)을 그대로 적용. $10k/$100k 두 규모.
4. **OOS 보호**: Holm 통과 시에만 구간 하위 40% 세그먼트 검증 (60/40 규칙).
5. **최종 승격**: Phase A 통과 + OOS 통과 → DSR(Deflated Sharpe Ratio) ≥ 0.95 → 사용자 승격 보고.
6. **fail-closed 원칙**: 데이터 누락·지연은 거래 생성 안 함(유리한 쪽으로 채우지 않음).

## §7. 정직한 종합 판정 (v14 최종)

1. **승격 후보 0건 확정** — 14건의 정식 측정이 전부 FAIL. "유능하다고 주장되는" 외부 전략의 수익 보고는 전부 제공자/저자 주장이며 본 플랫폼 규격으로 측정되기 전까지 유능 판정 아님.
2. **방향 원리 고갈** — cron 측정 큐 전부 소진 + 비겹침 신규 원리 스캔 완료(r3 17건 분류 + 누락분 X4/F3까지 측정). 현재 데이터·원리 공간에서 '엣지 ≥ 엔진 비용'인 방향 신호 부재가 입증됨.
3. **방향 엣지의 실체(최종)**: 14개 패밀리에서 반복 실측 — 엣지는 존재하나 원시 ±1~18bp = 엔진 비용(31~41bp)의 1/2~1/20. 예외적 비용 돌파 관측 2건(X1-R +21.7bp, F2/X6-R +36.2bp)은 표본 미달·사후 발견으로 판정 불가 — **신규 구간 데이터 축적이 유일한 해법**.
4. **루프 종료와 전환(cron 지시 §6 준용)**: ①N2 지정가 실행 계층(사용자 결정 대기) ②P3 90일 데이터 누적 대기 ③포트폴리오 계층 전환 ④X1-R·F2/X6-R 데이터 축적 후 재검증. 이 4개가 종료 후 실질 액션 목록.
