# 공개 시세로 비용 추정하기 — 내 PC에서 실행하는 방법

이 안내서는 바이낸스 **공개 시세 API**로 호가 데이터를 모아서 스프레드와 시장 충격을 추정하는 방법을 설명합니다. 계정, API 키, 로그인은 필요 없고 주문 기능도 없습니다. 연구 서버에서는 바이낸스 접속이 막혀 있어서, 데이터 수집은 내 PC에서 해야 합니다.

결과는 **"추정 근거 있음(ESTIMATED_FROM_PUBLIC_DATA)"** 등급입니다. 공개 호가는 실제 체결이 아니므로 "검증됨"으로 인정되지 않습니다. 이 등급으로 연구를 돌려도 전략이 페이퍼·실전 후보로 올라가지는 않습니다. 수수료도 공개 데이터로는 확인할 수 없으므로 공개 수수료표 기준 가정값(taker 0.05%)을 그대로 씁니다.

## 준비물
- 인터넷이 되는 PC (Windows, macOS, Linux 모두 가능)
- 수집하는 동안(약 3~4일) PC를 켜 두기. 절전 모드는 꺼 주세요.
- 저장 공간 약 200MB

## 1단계: 파이썬 설치
1. https://www.python.org/downloads/ 에서 Python 3.11 이상을 설치합니다.
   - Windows에서는 설치 첫 화면의 **"Add python.exe to PATH"**에 체크하세요.
2. 터미널을 엽니다. Windows는 시작 메뉴에서 "명령 프롬프트", macOS는 "터미널"을 실행합니다.
3. 설치를 확인합니다.
   - Windows: `py -3 --version`
   - macOS/Linux: `python3 --version`

   `Python 3.11` 이상이 보이면 됩니다. 추가로 설치할 패키지는 없습니다(표준 라이브러리만 씁니다).

## 2단계: 코드 받기
- git이 있으면: `git clone https://github.com/tlsehd195/new2-strategy-archive.git`
- git이 없으면: https://github.com/tlsehd195/new2-strategy-archive/archive/refs/heads/main.zip 을 브라우저에서 열어 ZIP을 받고 압축을 풉니다. 코드가 업데이트되면 **ZIP을 새로 받아야** 합니다. 예전에 받은 폴더에는 새 파일이 없습니다.

받은 폴더 안의 `run\discovery`로 이동합니다. 아래는 Windows 예시입니다. 폴더 이름과 위치를 본인 것으로 바꾸세요.

```
cd C:\Users\내이름\Downloads\new2-strategy-archive-main\run\discovery
```

(`cd`는 명령 프롬프트에서 폴더를 바꾸는 명령입니다. 이미 다른 폴더에 있어도 위 경로를 통째로 입력하면 이동합니다. "지정된 경로를 찾을 수 없습니다"가 나오면 폴더 이름이 다른 것이니 탐색기에서 `run` 폴더를 열어 주소창의 경로를 복사해 쓰세요. 수집·추정 스크립트는 Windows와 macOS에서 모두 추가 설치 없이 돌아갑니다.)

## 3단계: 연결 확인 (1분)
```
py -3 public_market_collect.py --allow-network --hours 0.02 --out ../../data/public_market_test
```
macOS/Linux에서는 `py -3` 대신 `python3`을 씁니다(아래 명령도 모두 같습니다).

끝나면 `"OK"` 개수가 0보다 큰지 확인하세요.

- `FETCH_FAILED`만 나오고 `EXCHANGE_ERROR`가 보이면 바이낸스가 이 지역의 접속을 막은 것입니다(HTTP 451/403). **VPN 등으로 우회하지 마세요.** 이용약관 위반입니다. 이 경우에는 스레드에 알려 주세요.
- `PROXY_ERROR`가 보이면 회사나 학교 네트워크의 차단일 수 있습니다. 집 인터넷에서 다시 해 보세요.

## 4단계: 본 수집 (약 80시간)
```
py -3 public_market_collect.py --allow-network --hours 80 --out ../../data/public_market
```
- 30초마다 BTCUSDT·ETHUSDT의 호가 50단계, 직전에 마감된 15분봉 거래대금, 최근 체결 100건을 저장합니다.
- 중간에 멈춰도 괜찮습니다. Ctrl+C로 멈췄다가 **같은 명령을 다시 실행하면** 이어서 쌓입니다. 다만 멈춘 시간은 "수집 공백"으로 집계되고, 전체의 2%를 넘으면 추정이 거부됩니다.
- 추정에 필요한 최소 조건은 종목별 72시간 이상, 스냅샷 2,000개 이상입니다. 공백을 감안해 80시간을 권합니다.

## 5단계: 추정 실행 (몇 초)
먼저 **최신 코드를 다시 받으세요**(2단계). 2026-10-17에 추정 기준이 v2로 더 엄격해졌습니다. 이미 모은 데이터는 그대로 쓸 수 있습니다(파일 형식은 같습니다).

수집이 Ctrl+C나 시간 만료로 끝났다면 `collect_manifest.json`이 이미 있습니다. 창을 닫거나 PC가 꺼져서 끝났다면 이 파일이 없거나 오래된 것이니, 네트워크 없이 다음을 한 번 실행해 파일 해시를 봉인하세요.
```
py -3 public_market_collect.py --manifest-only --out ../../data/public_market
```

그다음 추정을 실행합니다.
```
py -3 public_cost_estimate.py --in ../../data/public_market --out ../../data/public_market/estimate_v1.json
```
- `"status": "ESTIMATED_FROM_PUBLIC_DATA"`가 나오면 성공입니다.
- `INSUFFICIENT_PUBLIC_DATA`가 나오면 `reasons`에 부족한 조건이 적혀 있습니다. 수집을 더 한 뒤, **다른 파일 이름**(`estimate_v2.json` 등)으로 다시 실행하세요. 기존 결과 파일은 덮어쓰지 않습니다.
- v2 기준에서 추가로 거부되는 것: 매니페스트에 없거나 해시가 다른 파일(전송 중 손상 포함), 오래된 호가(5초 초과)·오래된 15분봉, 같은 시각 중복, 숫자가 아닌 값. 호가 50단계로 주문 크기를 다 채우지 못한 스냅샷이 1%를 넘는 주문 크기는 시장 충격 적합에서 통째로 빠집니다.
- 결과를 다시 확인하려면(새 기록을 만들지 않음): `py -3 public_cost_estimate.py --verify ../../data/public_market/estimate_v1.json --in ../../data/public_market` 종료 코드 0이면 원본 해시와 재계산 결과가 기록과 같습니다.

## 6단계: 결과 올리기
**쉬운 방법 (권장)**: `data/public_market` 폴더 전체를 zip으로 압축해서 이 프로젝트 채팅에 올려 주세요. Claude가 원본 해시를 확인하고, 추정을 다시 계산해 저장소에 기록합니다. 압축 파일은 수십 MB 정도입니다.

**GitHub로 직접 올리는 방법**:
1. 저장소 페이지에서 **Add file → Upload files**를 누릅니다.
2. `estimate_v1.json`과 `collect_manifest.json`을 끌어다 놓습니다.
3. 아래쪽에서 **"Create a new branch"**를 선택한 뒤 **Propose changes**를 누릅니다.
4. 원본 `.jsonl` 파일은 커서 웹 업로드가 어려우니, 원본은 위의 채팅 업로드 방법으로 보내 주세요.

## 자주 묻는 것
- **계정이나 키가 필요한가요?** 아니요. 코드는 키가 필요한 주소나 서명 파라미터를 보내지 않도록 막혀 있습니다(테스트로 확인).
- **요청을 너무 많이 보내지 않나요?** 30초마다 종목당 요청 3개를 보냅니다. 공개 한도보다 훨씬 적습니다. 간격은 `--interval`로 늘릴 수 있지만 5초보다 짧게는 설정할 수 없습니다.
- **추정값이 실제 비용과 같은가요?** 아닙니다. 숨은 물량, 대기열 순서, 지연을 근사할 뿐입니다. 그래서 보수적인 값을 씁니다. 스프레드는 90번째 백분위수에 한 수집 간격 동안의 가격 움직임을 더하고, 매수·매도 중 더 비싼 쪽을, 시장 충격은 두 추정치 중 큰 값을, 종목 간에는 더 비싼 쪽을 씁니다. 그래도 "검증됨"이 되려면 실제 체결 기록이 필요합니다.
