# ADR 0019 — 더 강한 후보 탐색(DEV 전용)과 MAP-Elites 부모 선택 비교

- 상태: Accepted (탐색 결과), MAP-Elites는 DEV 전용 선택 옵션으로만 추가
- 날짜: 2026-10-21
- 범위: `run/strong_search_dev.py`(신규), `run/iw1_statistic_dev.py`(신규), `run/compare_selection_dev.py`(신규), `run/discovery/search.py`(`selection`, `map_cell`, `select_elite_map`), `run/discovery/autoloop.py`, `run/discovery/runner.py`(`--selection`), `run/discovery/tests/test_map_elites_20261021.py`(신규), `run/discovery/README.md`, `run/audit/dev_search_trials.jsonl`(신규), `run/audit/evidence_strong_search_20261021/`, `run/audit/evidence_map_elites_20261021/`
- 선행: [ADR 0015](0015-dev-only-candidate-generation-r6.md)(R6), [ADR 0016](0016-independent-window-2020-market-cap-tranches.md)(IW1), ADR 0017(논문 검토), [ADR 0018](0018-short-and-long-short-support-check.md)(롱숏 묶음)
- 사용자 요청: 동동, 2026-10-21. "연습 구간 성적이 훨씬 좋은 후보 찾을 수 있어?" 이어서 논문 검토 스레드의 추천(MAP-Elites 지도 하나를 DEV에서 같은 예산·시드로 비교)에 "추천으로 진행".

## 맥락
- IW1은 한 번만 쓸 수 있다. 검정력 점검(ADR 0016)에 따르면 80% 확률로 통과하려면 연 샤프 약 2.8 이상이 필요하다. R6 DEV 통과 64개는 연 0.7~1.2라 IW1을 열지 않기로 했다.
- 질문은 "DEV에서 훨씬 강한 후보가 실제로 있는가"이다. DEV 점수만 올리는 탐색은 우연 통과를 늘리므로 탐색 횟수 보정과 안정성을 함께 본다.
- IW1, BTC/ETH 검증 구간, 잠금 TEST, 페이퍼 구간은 열지 않았다. 통계·비용 기준은 바꾸지 않았다. 실주문과 NEW2 연결은 없다.

## 1. 강한 후보 탐색 (`strong_search_dev.py`)
- **측정값은 IW1과 같다.** 규칙을 IW1 묶음 A의 6종목(BTC, ETH, BNB, XRP, TRX, ZEC)에 적용하고 일별 순수익(bp, 청산일 기록)을 같은 비중으로 평균한다. 비용은 IW1과 같은 `assumed_public_v1`이다.
- **읽는 구간.** S1 = 2021-01-01~2023-09-18(6종목, 모든 선택은 여기서). S2 = 2024-06-19~2025-10-20(BTC 제외 5종목, 보고만). 다음은 읽지 않고, 읽으려 하면 멈춘다: 2020년(IW1), 2023-09-19~2024-06-18(BTC 검증·잠금 구간, ADR 0010 때문에 모든 종목), BTC 잠금 이후(페이퍼), 2025-10-21 이후(ETH 검증·잠금·페이퍼).
- **데이터 구멍.** 알트 묶음의 XRP·TRX·ZEC는 2022-02-26~28, 2022-04-01~02 봉이 없다. 채우지 않고 구간을 나눴다(나눈 뒤 30일은 지표 준비).
- **평가기 일치.** 빠른 평가기의 거래를 엔진(`build_spec_signal` + `run_event_study`)과 비교했다. 상위 6개 × 2종목(증거 파일 `engine_crosscheck`)과 개발 중 무작위 4개 × 2종목 모두 거래 목록과 순수익이 같았다.
- **시도.** 규칙 언어 안(Track A) 3,795개: 단일 조건 3,132개(10개 지표 계열, 롱·숏·양방향, 보유 4~192시간) + 상위 40개 규칙에 필터 17개를 붙인 663개. 규칙 언어 밖(Track B) 62개: 몇 주 단위 추세, 종목 간 모멘텀·반전, 펀딩 캐리. 합계 3,857개를 전부 시도 횟수로 센다.

| 항목 | 값 |
|---|---|
| Track A 최고 S1 연 샤프 | 1.04 |
| 아무 실력 없는 3,857개 중 최고의 기대값 | 2.30 (독립 시도로 환산 93개 기준 1.59) |
| 상위 25개 대표의 DSR | 모두 약 0 |
| Track A S1 연 샤프 분위수 | 중앙 -2.09, 90% 0.04, 99% 0.67 |
| PBO(CSCV, 16조각) | 0.07, 단 표본 안 최고의 표본 밖 연 샤프 중앙값 -0.90 |
| Track B 최고 | 0.53 (30일 추세 롱숏, 주간 리밸런싱) |
| 상위 대표 10개·25개 묶음 S1 | 1.76·1.81 (같은 데이터로 고른 묶음) |
| 6종목 단순 보유 | S1 0.07, **S2 2.02** |

- 상위 규칙은 거의 모두 롱이고 "펀딩 z 낮음 + 단기 변동성 확대" 또는 "4일 수익 z 큼 + 거래대금 증가"였다. S1 상위 300개는 S2에서 중앙 1.18로 좋아 보이지만 S2는 단순 보유만 해도 2.02인 상승 구간이다. 상위 300개 안에서 S1 순위와 S2 순위의 상관은 -0.08이다. 즉 S1 상위는 "비용에 잡아먹히지 않는 롱 노출"이라는 점만 S2로 이어지고, 순위의 실력은 이어지지 않는다.
- PBO가 낮은 것은 대부분의 시도가 비용 때문에 크게 음수라 "비용에 덜 지는 규칙"을 고르는 것만으로 표본 밖 중간 순위를 넘기 때문이다. 고른 후보의 표본 밖 샤프 자체는 음수다.
- 묶음은 IW1 사전등록(후보 하나씩 검정)으로 검정할 수 없다. 묶음을 쓰려면 v2 사전등록이 필요하고, 그 숫자도 선택 편향이 있다.

## 2. MAP-Elites 부모 선택
- **구현.** `SearchConfig.selection = "map_elites"`이면 부모를 칸마다 1개씩 고른다. 칸 = 방향(롱/숏/양방향) × 보유 구간(32·128·384·768봉 이하) × 신호군(진입 조건의 지표 종류). 칸 안에서는 DEV 통과 우선, 그다음 상한 6의 DEV t, 접힘 양수 비율, 낙폭 순이다. 자격은 기존과 같다(DEV 평균 > 0). 부모는 차 있는 칸에서 균등하게 뽑힌다. 변형 연산자, 평가, 통과 기준, 중복 제거는 바꾸지 않았다.
- **기본값 불변.** 기본은 `pareto_niche`이고 설정 해시도 그대로다. 다만 코드 파일 해시가 바뀌어 컨텍스트 id는 새로 생긴다(`C2-4249176cda367b00a3ab`). 이 컨텍스트에서 기본 방식 8라운드는 R6와 같은 894개 평가, 같은 64개 통과, 같은 방향 구성(롱 56, 숏 3, 양방향 5)을 냈다. R6 컨텍스트 `C2-f64e…`를 정확히 다시 만들려면 이 변경 이전 커밋으로 돌려야 한다(ADR 0016의 재고정 절차에 해당).
- `--selection map_elites`는 `--mode evolve --dev-only`에서만 받는다. 검증 단계로는 이어지지 않는다.

### 같은 시드·예산 비교 (공개 호가 추정 비용, BTC/ETH 엔진 DEV, 시드 705개 동일)
| | 기존 8R | MAP 8R | 기존 24R | MAP 24R |
|---|---|---|---|---|
| DEV 평가(전체) | 894 | 897 | 1,277 | 1,281 |
| 제안 / 무효 | 189 / 103 | 192 / 31 | 572 / 201 | 576 / 89 |
| 마지막 라운드 부모 수 | 12 | 37 | 12 | 71 |
| 진화 자식 DEV 통과 | 39 | 32 | 42 | 99 |
| 자식 통과 방향 (롱/숏/양방향) | 34/0/5 | 19/2/11 | 36/0/6 | 70/7/22 |
| 자식 통과가 차지한 칸 | 12 | 13 | 13 | 35 |
| 자식 통과 최고 DEV 연 샤프 | 1.20 | 1.17 | 1.37 | 3.06 |

- 8라운드에서는 MAP-Elites가 무효 제안을 크게 줄이고 숏·양방향 통과를 늘렸지만 통과 수와 최고 점수는 조금 낮았다. 24라운드에서는 통과 99개, 칸 35개로 다양성이 분명히 늘었다. 기존 방식은 부모 12개에 머물며 롱 위주였다.
- **연 3.06·2.85 후보는 강한 후보가 아니다.** 두 후보는 같은 계열이다(RSI>80, 거래대금 z, 돌파 + 25bp 익절, BTC만 거래). 공개 호가 추정 비용에서 BTC 왕복 비용이 낮아 25bp 익절이 거의 매번 순이익으로 남은 결과다. IW1 조건(6종목, `assumed_public_v1`)으로 다시 재면 S1 연 -4.27·-3.86, S2 -4.89·-4.46이고 순이익 거래 비율은 3%다(`iw1_statistic_top_dev.json`). 같은 점검에서 MAP 24R 상위 12개와 기존 24R 상위 5개 모두 S1에서 0.38 이하였다. 알트의 가정 비용(시장 충격 포함)이 커서 거래가 잦은 규칙은 IW1에서 버티기 어렵다.
- 결론: MAP-Elites는 같은 예산에서 탐색 범위를 넓히는 데는 효과가 있었다(특히 긴 예산에서). IW1을 열 만큼 강한 후보는 어느 방식에서도 나오지 않았다. 통과 수가 늘어난 만큼 우연 통과도 늘어나므로 통과 수를 품질로 읽으면 안 된다.

## 결정
- IW1은 계속 닫아 둔다. 다시 제안할 조건(IW1 측정값 기준 연 2.8 이상 기대)은 그대로다.
- MAP-Elites는 DEV 전용 옵션으로 남긴다. 기본 선택 방식은 바꾸지 않는다. 기본으로 바꿀지는 별도 결정이다.
- 모든 시도 수를 `run/audit/dev_search_trials.jsonl`에 기록했다(이번 스레드 합계: 강한 후보 탐색 3,857, evolve 4개 실행 894·897·1,277·1,281, 재채점 17). 시드 705개는 네 실행에서 같은 정의를 다시 평가한 것이다.
- 기준값(`promotion_v3.json`, 비용 프로필, 잠금 창, IW1 사전등록)은 하나도 바꾸지 않았다.

## 한계
- S1은 약 2.5년이고 2021~22 상승·하락이 대부분이다. S2는 ETH 부분이 엔진 DEV에 이미 포함되어 있고 BTC 페이퍼 기간과 시기가 겹친다(BTC 데이터는 읽지 않음). 독립 검증이 아니다.
- 청산일 기록 방식이라 일별 수익이 뭉쳐 있다. 단순 보유와의 상관은 이 방식 차이 때문에 0에 가깝게 나와 시장 노출 판단에는 쓰지 않았다.
- 엔진 DEV(BTC/ETH, 공개 호가 추정 비용)와 IW1 측정값(6종목, 가정 비용)은 결과가 크게 다를 수 있다. 엔진의 DEV 통과는 IW1 통과 가능성을 거의 말해 주지 않는다.
- 논문 근거: Mouret & Clune 2015(arXiv 1504.04909)는 금융 검증이 없는 초안이다. 이번 비교도 시드 1개, 예산 2개 지점뿐이다.

## 다음 단계(제안, 사용자 결정)
- 후보 탐색과 엔진 DEV 선별 단계에 IW1과 같은 비용·종목 기준을 함께 쓰면, 엔진에서는 통과하지만 IW1에서는 무너지는 후보를 미리 거를 수 있다(기준 강화 방향).
- 묶음이나 종목 간 전략을 IW1에서 검정하려면 IW1을 열기 전에 v2 사전등록이 필요하다.
