# ADR 0068 — evolve 포트폴리오 검증 계층(portfolio-validation-v1)

- 상태: Accepted (코드·기준 신설, 기존 기준 불변)
- 날짜: 2026-11-10
- 요청: 동동, 2026-11-10 "잔여 문제 전면 해결" 지시문 §2 (P0), 감사 문제 P-01
- 관련: ADR 0064(promo-v5), ADR 0063(비용 구성요소 표), `run/audit/AUDIT_FULL_20261110.md` P-01

## 맥락
- evolve 경로(`pipeline.EvolutionPipeline`)는 전략 하나의 이벤트 수익만 심사했다.
  - DEV 선별 → 검증 창 StepM → robustness → 잠금 캠페인 → 승격 심사.
  - 자본, 사이징, 레버리지, 증거금, 청산, 여러 전략 동시 보유는 어디에서도 계산하지 않았다.
- `portfolio.simulate_portfolio`(legacy 경로)는 전략 하나만 다룬다.
  - 종목당 포지션 1개, 시간 청산만 지원하고 손절·익절, 전략별 기여, 교차 증거금이 없다.
  - legacy 결과의 `model_version`을 바꾸지 않기 위해 이 함수는 그대로 둔다.
- 감사(ADR 0067)는 "잠금 창 이후에 게이트를 두면 사후 판정"이라며 설계를 미뤘다.
  - 지금까지 기록된 모든 컨텍스트에서 VALIDATION_SURVIVOR는 0건이다.
  - 따라서 지금 기준을 고정하면 어떤 결과도 보기 전의 사전 고정이 된다.

## 결정
1. **새 모듈 `run/discovery/portfolio_multi.py` (`portfolio-multi-v1`).**
   - 계좌 하나를 봉 단위 시간 순서로 갱신한다. 전략 수익을 더하지 않는다.
   - 봉마다 순서: ① 펀딩 정산(직전 봉 < t ≤ 현재 봉) ② 시가 청산(시간 청산·갭) ③ 시가 진입 ④ 봉 내부 청산·손절·익절 ⑤ 종가 평가.
   - 자본: 전략별 동일 가중 배분, 종목 수로 나눈 주문 크기, 동시 보유 상한, 총 익스포저 상한, 포지션별 증거금 예약(중복 사용 불가), 여유 증거금이 없으면 진입 거절.
   - 증거금: isolated(포지션별 증거금 손실)와 cross(봉의 불리한 극값을 모든 포지션에 동시에 적용해 계좌 자본이 유지증거금 합 이하면 전부 청산).
   - 비용: `CostContext.quote`로 실제 명목가에서 다시 계산한다. 수수료와 스프레드·충격을 나눠 기록한다. 펀딩은 실제 정산 시각에 현금으로 반영한다.
   - 가격을 매길 수 없는 청산은 비용 0으로 넣지 않는다. 결과를 `UNPRICED_EXIT`로 표시해 UNDETERMINED가 된다.
   - 부분 체결과 체결 지연은 `NOT_MODELLED`로 표시한다. 스트레스 값(`fill_ratio`, `latency_bars`)은 보정되지 않은 진단용이다.
   - 같은 종목: hedge(양방향 각각 비용 부담, 상계하지 않음) 또는 one_per_symbol. 같은 전략의 중복 신호는 크기를 늘리지 않는다.
   - 동시 신호 우선순위: 구성원 순서(전략 id 정렬) → 종목.
   - 시간 무결성 오류는 `PortfolioInputError`가 되고, 결과는 PORTFOLIO_SIMULATION_ERROR가 된다.
     - 결정 봉 ≥ 진입 봉, `as_of` 이후 결정(미래 정보), 정렬되지 않거나 중복된 봉, 봉 범위 밖 청산가, 비정상 봉.
   - 같은 봉에서 청산과 손절·익절이 모두 가능하면 손실이 큰 쪽을 기록한다.
   - 지표마다 상태를 둔다. 계산할 수 없으면 `NOT_COMPUTABLE`과 이유를 남기고 0으로 채우지 않는다.
     - Sharpe·Sortino는 일 30개 미만, CAGR·Calmar는 365일 미만, Profit Factor는 손실 거래가 없을 때 계산하지 않는다.
2. **기준 파일 `config/portfolio_validation_v1.json` (promo-v5와 분리).**
   - promo-v5는 한 글자도 바꾸지 않는다. 개별 전략 기준과 포트폴리오 기준을 별도 파일·별도 해시로 관리한다.
   - 시나리오 3개:
     - `base`(isolated 1배, 판정): 최종 자본 > 초기 자본, MDD < 0.5, 청산 0, 파산 없음, 청산 거래 30건 이상, 30일 이상.
     - `stress_cross_3x`(cross 3배, 판정): 청산 0, 파산 없음.
     - `stress_partial_latency`(체결 50%·지연 1봉, 진단만).
   - 수치 기준은 새로 만들지 않았다. base는 `portfolio.PORTFOLIO_PASS_CRITERIA`와 promo-v5 검증 표본 최소값(30건·30일)을 그대로 쓴다.
   - 기준 파일 해시는 실험 컨텍스트(`validation.portfolio_config`)에 들어간다.
3. **파이프라인 연결(추가 계층, 기존 판정 대체 아님).**
   - robustness를 통과해 VALIDATION_SURVIVOR(= PASS_INDIVIDUAL)가 되면 곧바로 `portfolio_validation(sid)`을 실행한다.
   - 결과는 평가 기록 `stage = "portfolio"`로 따로 저장한다. 개별 상태(statuses.jsonl)는 바꾸지 않는다.
     - 상태: PASS_PORTFOLIO, FAIL_PORTFOLIO, INSUFFICIENT_PORTFOLIO_DATA, UNDETERMINED_PORTFOLIO, PORTFOLIO_SIMULATION_ERROR.
   - 구성: 단독(후보만)과 결합(후보 + 장부). 장부는 같은 컨텍스트에서 PASS_PORTFOLIO이고 현재 REJECTED·INCONCLUSIVE·PAPER_FAILED가 아닌 전략이다. 가중치는 동일하며 자료로 맞추지 않는다.
   - 둘 다, 판정 시나리오 모두 PASS여야 PASS_PORTFOLIO다(가장 나쁜 상태를 취함).
   - 잠금 캠페인은 PASS_PORTFOLIO만 받는다. 실패한 전략 때문에 잠금 창을 쓰지 않는다.
   - 승격 심사는 PASS_PORTFOLIO가 아니면 실패 사유를 남기고, 포트폴리오 기록 id를 증거에 넣는다.
   - 중단 복구: `resume_pending_portfolio()`(autoloop가 매 사이클 호출). 기존 기록이 있으면 그대로 돌려주고 다시 쓰지 않는다.
   - 사이클 요약에 `portfolio_report`(개별·포트폴리오 결과 나란히)와 `portfolio_status_counts`를 더한다.
4. **자료와 누수.**
   - 자료는 구성원 종목의 검증 창뿐이다. 이 창은 해당 전략의 StepM·robustness가 이미 읽었다.
   - 잠금 TEST, IW0/IW1, 봉인 자료는 읽지 않는다. 테스트로 `locked_loads == 0`을 확인한다.
   - 같은 창에서 이미 선택된 전략이므로 PASS는 엣지의 증거가 아니라 계좌 위험에 대한 필요조건(거부 전용)이다.
   - 선택 편향 기록: `selection_record.portfolio_checks_before_in_context`, 장부 크기, 구성원 목록.

## 결과
- 새 테스트 `tests/test_portfolio_multi_20261110.py`(합성 자료).
  - 단일·다중 전략, 동시 진입·우선순위, 같은 방향 중첩, 반대 방향, one_per_symbol, 중복 신호, 비활성 전략.
  - 자본 감소와 증거금 부족, isolated 청산, cross 동시 손실 계좌 청산, 같은 봉 손절·청산 충돌, 시가 갭.
  - 펀딩(롱 지급·숏 수취), 펀딩 미포함 → INSUFFICIENT, 부분 체결·지연, 참여율 거절, 거래대금 결측, 가격 불가 청산 → UNDETERMINED.
  - 신호 봉 체결, 미래 결정, 정렬·중복 오류, 불가능 청산가, 비정상 봉, 봉 누락, 결정성.
  - 지표 NOT_COMPUTABLE, 파이프라인 분리 저장, FAIL이면 잠금 창 미사용, 자료 결손 구성원, 오류 구성원, 중단 후 1회 재개, 결합 구성, 승격 차단, 컨텍스트 포함.
- `test_pipeline` 정상 경로 테스트: 승격 증거 집합에 `portfolio`가 더해졌다(기준 약화 아님).
- 기존 결과와의 호환성:
  - `pipeline.py`와 새 파일이 코드 해시에 들어가므로 새 컨텍스트가 된다.
  - 기존 상태·평가는 지워지거나 덮어써지지 않는다. 옛 컨텍스트 기록은 그대로 남는다.
  - 기존 컨텍스트에 생존자가 0건이라 다시 판정해야 할 결과는 없다.
- 통계적 유효성: 거부만 더하는 계층이므로 FWER·알파 소비는 그대로이며 늘어나지 않는다.

## 독립 검토와 반영(Fable 5.2, 읽기 전용 검토)
첫 구현을 별도 검토로 확인했다. 확인된 결함 7건은 모두 고쳤고 회귀 테스트(`TestReviewFixes` 등)를 더했다.
1. 지연 스트레스가 지연 구간 안에서 손절될 거래를 미리 알고 건너뛰었다(빠른 손실만 빠지는 낙관 편향).
   - 이제는 늦은 진입에서 전략 자신의 청산 규칙(`stop_exit_rule`)으로 청산을 다시 계산하고 거래를 버리지 않는다.
   - 규칙 없이 봉 내부 청산에 지연을 걸면 오류다.
2. `fill_ratio`가 포지션만 줄여 오히려 안전해 보였다.
   - 이제는 나머지가 다음 시가에 자기 가격과 비용으로 체결된다. 그 시가가 청산 이후면 취소되고 미체결로 기록한다.
3. 총 익스포저 상한에 레버리지가 곱해져 한 번도 작동하지 않았다.
   - 이제는 명목가 합 / 자본으로 비교한다. 3배 스트레스는 설정에 3.0을 명시한다.
4. 진입 시가 = 청산 시가(보유 0)인 거래가 끝까지 남았다. 이제는 입력 오류로 처리한다.
5. 배분을 실제 거래가 나온 종목 수로 나눴다(창 전체 정보). 이제는 spec 종목 수로 나눈다.
6. `trades_from_events`가 봉 범위 밖 청산가를 몰래 잘라 맞췄다. 이제는 부동소수 오차만 허용하고, 나머지는 시뮬레이터가 오류로 잡는다.
7. 청산이 이기는 봉에서도 손절 비용을 먼저 매겨, 비용 거절이면 FAIL이 UNDETERMINED로 바뀌었다. 이제는 손실을 먼저 비교하고 기록되는 체결만 비용을 매긴다.
8. 기준 파일의 모르는 check 키는 이제 오류다(오타로 기준이 빠지지 않게).

## 한계(모델 가정, 거래소 규칙 아님)
- 청산가 공식, 유지증거금률 0.5%, isolated 청산 손실 = 증거금, cross 극값 동시 가정은 설정값이다.
- 거래소 단계별 증거금, 보험 기금, ADL, 마크가격은 모델링하지 않는다.
- 부분 체결·지연·변동성 의존 비용은 실체결 자료가 없어 NOT_MODELLED다. 비용 상태가 VERIFIED가 아니면 `cost_components.complete = false`다.
- 장부 구성은 먼저 통과한 전략에 따라 달라진다(경로 의존). 기록에 구성원과 순번을 남긴다.
- 장부는 고정·경로 의존이다. 먼저 들어간 구성원은 나중 후보와 다시 결합 시험을 받지 않는다. 컨텍스트 안의 ERROR·UNDETERMINED·INSUFFICIENT 기록도 영구적이다. 장부는 id 순으로 20개까지만 쓴다.
- 결합 판정은 계좌 단위다. 한계 기여가 음수인 후보도 장부가 받쳐 주면 결합은 통과할 수 있다. 그래서 단독 판정도 함께 요구한다.
- 낙폭·파산은 봉 종가 기준이고, 명목가는 진입가 기준이다(재평가하지 않는다).
- isolated 청산 손실은 갭으로 청산가를 뚫어도 증거금으로 고정된다.
- `cost_components.complete`는 NOT_MODELLED 항목이 남아 있는 한 항상 false다.
- 합성 자료 테스트는 계산 규칙만 확인한다. 실제 시장 성과에 대한 주장이 아니다.
