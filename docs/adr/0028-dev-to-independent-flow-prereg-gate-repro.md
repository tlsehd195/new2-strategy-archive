# ADR 0028 — DEV에서 독립 검증까지의 흐름 연결, 사전등록 활성화 게이트, 재현성 번들

- 상태: Accepted (코드·테스트 변경. 통계 기준·비용 가정은 바꾸지 않음)
- 날짜: 2026-10-22
- 범위: `run/discovery/` (pipeline.py, runner.py, independent_window.py, evolution_report.py, README.md,
  새 모듈 validation_registry.py, prereg_gate.py, repro_bundle.py, cost_sensitivity.py, behaviour_overlap.py),
  `run/discovery/tests/test_pipeline_flow_20261022.py`, `run/LEGACY_SCRIPTS.md`, `.github/workflows/research-ci.yml`
- 감사 보고서: `run/audit/AUDIT_PIPELINE_20261022.md`
- 사용자 요청: 동동, 2026-10-22 ("NEW2 Strategy Archive 전체 감사 및 연구 파이프라인 문제 해결 지시문")

## 맥락
최신 코드(`338654c`, PR #22까지 병합, CI 성공)에서 지시문 1~9항을 다시 확인했다. DEV 평가, 중복 제거,
BTC/ETH 검증 배치(상태 원장과 연결됨)는 동작했다. 그러나 다음이 비어 있거나 틀려 있었다.

1. **검증 배치 재시작 결함(재현).** 배치 평가 중 한 멤버의 상태(REJECTED)를 기록한 뒤 RESULT 줄을 쓰기 전에
   멈추면, 재실행이 `REJECTED -> REJECTED` 전이 오류로 **영구히** 실패하고 검증 기록이 두 번 쌓였다.
2. **DEV 상태 누락 결함(재현).** DEV 평가 기록을 쓴 뒤 상태 기록이 실패하면, 재실행은 기록이 있다는 이유로
   바로 돌아가 상태를 끝내 쓰지 않았다. 그 후보는 검증 후보에서도, 탈락 집계에서도 빠졌다.
3. **독립 검증의 등록·실행·완료 기록이 없었다.** `independent_window.py open`은 창 사용 줄(history)만 먼저 쓰고
   결과 파일을 덮어쓸 수 있었으며, 결과는 어떤 상태 원장에도 연결되지 않았다. 평가 도중 멈추면 창은 소비된 채
   결과도, "미완료" 표시도 남지 않았다.
4. **사전등록 활성화 판정이 코드에 없었다.** v2 초안의 "효력 없음"은 문장일 뿐이었고, IW1 열기는 사전등록이
   승인됐는지 확인하지 않았다. 멤버 파일에는 동결 당시 평가 코드 버전이 없었다.
5. 보고서가 DEV·BTC/ETH 검증·독립 검증을 한 표에서 구분하지 않았고, 중복 제거 수치(30/15)는
   **거절 결정 횟수**였지 서로 다른 정의 수가 아니었다(같은 정의가 여러 번 거절됨).
6. 비용 민감도는 `robustness`의 총비용 배수(검증 통과 후보만)뿐이었다. 수수료·스프레드·충격·주문 크기를
   따로 바꾸는 DEV 진단이 없었다.
7. CI는 `run/test_*.py`(DEV 도구 테스트 9개)를 실행하지 않았다. `runner.py`의 데이터 경로 기본값이
   폐기된 v1 서버 경로였고, `run/`의 구 스크립트 78개가 NEW2 패키지나 v1 경로를 참조했다.

## 결정
1. `pipeline._evaluate_batch`: 재개된 배치는 같은 배치의 기존 검증 기록을 재사용하고(재계산 결과와 다르면
   `EvidenceTampered`), 이미 그 기록으로 쓴 상태는 다시 쓰지 않는다.
2. `pipeline.dev_evaluate`: 기록은 있는데 상태가 없으면 저장된 기록에서 상태를 쓴다(재평가하지 않음).
3. **`validation_registry.py`** — 해시 체인 append-only 원장. `REGISTERED → STARTED → COMPLETED`,
   `ABORTED`, `INVALIDATED`. 등록은 멤버 id와 정의 해시, 사전등록·멤버 파일 해시, 평가 코드 해시, 설정, 비용을
   고정한다. 같은 id 재등록은 내용이 같을 때만 허용, 완료는 한 번만, 멤버·코드가 바뀌면 시작·완료 거부,
   손상된 줄·변조·체인 끊김은 읽기 자체를 실패시킨다. 독립 검증 결과는 여기에만 `stage=independent`로 남고
   DEV 상태 원장은 건드리지 않는다.
4. **`independent_window.open_tranche`** — ACTIVE 게이트 없이는 아무것도 열지 않는다. 순서: 검사 → 등록 →
   창 사용 줄 → 시작 → 평가 → 결과 파일(이미 있으면 거부, 덮어쓰지 않음) → 완료. 평가 도중 멈춘 실행은
   `RUNNING`으로 남아 "미완료"로 보고되고, `--resume`으로 같은 멤버·코드일 때만 이어서 끝낼 수 있다(창 사용 줄은
   다시 쓰지 않음, 결과는 그 전까지 아무도 보지 않았으므로 두 번째 조회가 아니다). 멤버 파일에 평가 코드 해시를
   넣는다.
5. **`prereg_gate.py`** — 생명주기 DRAFT / REVIEWED / ACTIVE / INVALID를 **증거에서 도출**한다. 파일이 스스로
   적은 상태나 날짜는 쓰지 않는다. ACTIVE 조건: 자기 해시가 맞는 활성화 기록(`prereg_activation_v1`), 사전등록과
   멤버 파일을 sha256으로 지정, 승인자·승인일·체크리스트 5항목 모두 참, 멤버 파일이 정규형·해시 일치·**현재 평가
   코드에 고정**, 세 파일이 git에 커밋되어 작업 트리에서 수정되지 않았고 마지막 커밋이 마감(전진 창은
   `window_start`) 이전. 초안 스키마(`*_DRAFT`)나 "NOT IN FORCE" 상태 문구는 항상 비활성. 스키마별 필수 필드
   (후보 규칙, 데이터 정의, 비용, 통계 기준, 창, 통과 조건, 1회 사용)를 검사한다. `window_status`는 ACTIVE가
   아니면 오늘 날짜와 무관하게 `NOT_STARTED`다.
6. **`repro_bundle.py`** — 커밋·작업 트리 상태, 평가 코드 파일별 해시, 후보 목록·정의 해시, 데이터 해시·기간·
   타임프레임, 비용 버전·파라미터·상태, 백테스트 설정, 시드, 통계·다중 검정 설정, 실행 명령, 결과 상태·실패
   원인. 인증정보처럼 보이는 키가 있으면 거부한다. 재현 불가 항목(시각, 파이썬 부 버전)은 `limits`에 적는다.
   독립 검증 결과에는 번들이 붙고(결과 해시 밖), DEV 상태 디렉터리는 `repro_bundle.py dev`로 만든다.
7. **`cost_sensitivity.py`**(DEV 진단, 관문 아님) — 같은 사건을 수수료 ×1.5/×2, 스프레드 ×2/×3, 충격 ×2,
   주문 크기 ×5/×25, 전부 ×2로 다시 계산하고 진입 변동성 상·하로 나눠 보고한다. 메이커 수수료 행은
   "낙관적 경계"로만 표시한다. 비싼 시나리오가 더 좋은 결과를 내면 `monotone_issues`로 잡는다.
   기준 비용이 VERIFIED가 아니면 "관측값 아님"을 기록한다.
8. **`behaviour_overlap.py`**(DEV 진단) — DEV 실제 거래(종목·진입 시각·방향·청산 시각)가 완전히 같은 후보를
   묶는다. 진입만 같고 청산(보유 기간·손절)이 다르면 묶지 않는다. 진입 Jaccard·방향 일치·청산 일치·평균 보유는
   보고만 한다. 후보 목록을 바꾸지 않는다(이 진단을 제거 정책으로 쓸지는 사용자 결정).
9. `evolution_report`: `independent`(등록 원장, 완료 실행만 집계, 미완료 목록 별도), `consistency`(중복 기록,
   상태 없는 DEV 기록, RESULT 없는 배치), 중복 제거의 서로 다른 정의 수를 추가. DEV 통과는 독립 검증으로
   집계되지 않는다는 문구를 표 위에 둔다.
10. `runner.py`: `NEW2_DATA_DIR` 기본값 삭제(설정 안 되면 실패). `run/LEGACY_SCRIPTS.md`: 구 스크립트 78개
    DEPRECATED 목록. CI: 독립성 grep 단계, `run/test_*.py` 실행, 현재 DEV 도구 컴파일 추가.
11. 기준 파일 고정 테스트: `promotion_v3.json`, `independent_window_v1.json`, `cost_assumed_public_v1.json`,
    `cost_verification_v1.json`의 sha256을 테스트에 고정한다. 기준을 바꾸려면 새 버전 파일과 ADR이 필요하다.

## 바뀌지 않은 것
- 알파, StepM, 최소 사건 수, DEV 선별 기준, 비용 프로필, 잠금 TEST·종이 거래·승격 규칙(ADR 0009/0010).
- IW1은 닫혀 있다(사용자 결정 2026-10-21). 사전등록 v2는 초안이다. BTC/ETH 검증·잠금 구간은 읽지 않았다.
- `pipeline.py`·`runner.py` 변경으로 평가 코드 해시가 바뀌어 **새 실험 맥락 id**가 생긴다. 예전 맥락의 증거는
  재사용되지 않는다(기존 규칙). IW1 멤버 파일(`IW1_members.json`)에는 코드 해시가 없으므로 IW1을 열려면
  재동결이 필요하다(게이트가 거부한다).
- e-값 누적 검증 설계 v3(ADR 0025, 같은 날 병합)의 파일은 건드리지 않았다. 원래 이 ADR 번호는 0025였으나 병합 순서상 0027로, 다시 0028로 바꿨다(0027은 PR #28이 사용). 게이트는 스키마별 규칙이라 v3 스키마가 생기면
  규칙을 추가해야 ACTIVE가 될 수 있다.
