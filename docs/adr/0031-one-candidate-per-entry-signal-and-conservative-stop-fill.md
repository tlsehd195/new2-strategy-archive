# ADR 0031 — 검증 배치에 진입 신호당 후보 하나, 손절 체결을 보수적으로

- 상태: Accepted (선정 규칙과 체결 가정만 바꿈. 통계 기준·비용 가정 파일은 그대로)
- 날짜: 2026-10-22
- 범위: `run/discovery/` (pipeline.py, evolution.py, strategy_spec.py, 새 설정 파일
  `config/candidate_selection_v1.json`, `config/exit_fill_v1.json`),
  `run/discovery/tests/test_selection_stopfill_20261022.py`, `tests/test_pipeline.py`(테스트 후보 교체)
- 사용자 요청: 동동, 2026-10-22 ("일단 너가 추천하는 걸로 진행하는데 추천하는 이유도 설명")
- 번호: 처음 0030이었으나 PR #29가 0030을 써서 0031로 바꿈
- 앞선 결정: [ADR 0029](0029-dev-to-independent-flow-prereg-gate-repro.md)의 진단 결과

## 맥락
ADR 0029의 R6 DEV 재실행 진단에서 두 가지가 보였다.

1. **청산만 다른 변형이 검증 후보를 채운다.** DEV 통과 64개를 진입 신호(방향·종목·봉 간격·진입 조건·필터의
   정규형)로 묶으면 33개뿐이었다(가장 큰 묶음 8개). 검증 후보 상위 10개는 진입 신호 4개였다. 실제 거래 비교에서도
   진입 일치율(Jaccard) 0.99 이상인 쌍이 많았다. 이런 변형은 같은 가설을 여러 번 보는 것이라, 배치에 같이 들어가면
   검증 배치의 크기(다중 검정 부담)와 알파 소비만 늘리고 새 정보는 거의 없다.
2. **손절 체결이 낙관적이었다.** 봉 안에서 손절가에 닿으면 정확히 손절가에 체결된다고 보았다. 실제 손절은 시장가로
   나가므로 급락 봉에서는 손절가보다 나쁘게 체결된다. 갭은 이미 시가로 처리했지만 봉 안 미끄러짐은 0이었다.

## 결정
1. **진입 신호당 대표 하나** (`config/candidate_selection_v1.json`, `one_per_entry_signal: true`).
   - `evolution.entry_signal_key`: 행동 키(`behaviour_key`)에서 청산(`exit`)만 뺀 해시. 임계값 근사 없이 정확히 같은
     진입만 같은 키가 된다.
   - `pipeline.validation_candidates`: 기존 순서(상한을 둔 DEV t, 그다음 id)에서 첫 번째만 배치에 넣는다. 같은
     문맥에서 이미 배치에 들어간 후보와 진입 신호가 같으면 그 뒤 후보도 빠진다(다시 보는 것도 같은 가설).
   - 빠진 후보는 RESEARCH_ONLY로 남고 `near_duplicate_skips()`에 대표 id와 이유가 기록된다. 상태를 바꾸거나
     지우지 않는다.
   - 기존 근접 중복 규칙(`one_per_near_duplicate`)은 그대로 둔다. 이 규칙은 후보를 빼기만 하고 더하지 않는다.
2. **손절은 봉의 가장 나쁜 가격에 체결** (`config/exit_fill_v1.json`, `stop_fill: "bar_extreme"`).
   - 봉 안에서 손절에 닿으면 롱은 그 봉의 저가, 숏은 고가에 체결한다. 손절가보다 좋게 체결되는 경우는 없다.
   - 시가가 손절가를 넘어 열린 봉은 지금처럼 시가에 체결(갭). 익절(지정가)은 바꾸지 않았다.
   - 예전 방식(`stop_price`)은 인자로만 남겼다(비교용). 기본값은 설정 파일에서 읽으므로 DEV, 독립 창, 페이퍼,
     비용 민감도가 모두 같은 가정을 쓴다.
   - 수수료·스프레드·충격 비용은 지금처럼 체결가 위에 따로 붙는다. 즉 손절 미끄러짐은 비용에 **더해질 뿐** 줄지 않는다.
3. 두 설정 파일을 `EVO_CODE_FILES`에 넣었다. 문맥 id와 사전등록 동결의 코드 해시가 바뀌므로, 이 변경 전의 DEV
   결과와 섞이지 않는다. 두 파일의 sha256 앞자리를 새 테스트에 고정했다. 기존 고정값(promotion_v3,
   independent_window_v1, cost_assumed_public_v1, cost_verification_v1)은 건드리지 않았다.

## 추천 이유
- 진입 신호당 하나: 배치의 검정 수가 줄면 같은 알파에서 각 후보의 검정력이 올라간다(Romano-Wolf StepM은 배치 안
  최대 통계량으로 기준을 정한다). 같은 진입의 변형을 여러 개 넣어도 독립된 증거가 늘지 않는다. 그리고 1/k² 알파
  지출에서 배치 하나를 아낀다. 대표만 고르는 것은 기준 완화가 아니다. 대표도 같은 기준을 통과해야 한다.
- 봉 극단가 손절: 이 프로젝트의 원칙은 "모르면 보수적으로"다. 실제 체결 자료(계정 체결 200건 이상)가 없으므로
  손절 미끄러짐을 추정할 근거가 없다. 그래서 봉 안에서 일어날 수 있는 가장 나쁜 값을 쓴다. 이 값보다 나쁘게 체결될
  수는 없다(그 봉 안에서 나간다면). 실제 체결 자료가 생기면 그 분포로 바꾸는 새 버전 파일을 만들 수 있다.

## 영향 (R6 DEV 전용 재실행, 검증 창·IW1은 열지 않음)
같은 명령을 이 코드로 다시 돌렸다(R7, 문맥 `C2-dc89a2574236479535ef`, 3450초, CYCLE_OK = 파이프라인이 돌았다는 뜻이지 전략 판정이 아님).
증거: `run/audit/evidence_selection_stopfill_20261022/`.

| | R6 (이전 코드) | R7 (이 결정) |
|---|---|---|
| DEV 평가 | 894 | 894 (같은 후보, 탐색 경로 동일) |
| DEV 통과(RESEARCH_ONLY) | 64 | 63 |
| 검정력 부족(INCONCLUSIVE) | 93 | 93 |
| 탈락(REJECTED) | 737 | 738 |
| 검증 배치 후보 | 64 (근접 중복 규칙만) | 33 (30개는 진입 신호가 같아 대표에게 양보) |

- 손절이 있는 후보는 894개 중 4개뿐이었다. 손절이 없는 890개의 DEV 지표는 R6과 완전히 같았다.
- 손절 4개의 DEV 순평균(bp)은 모두 내려갔다: 200.9→181.2, 35.2→21.1, −47.2→−66.2, 27.7→−14.6.
  마지막 것(`S-e9b22519727c25ec`, 손절 25bp)은 DEV 통과였으나 이제 탈락한다. 좁은 손절일수록 봉 안 미끄러짐이 크다.
- 진입 신호 묶음: 63개 → 33개. 검증 배치에 같은 가설이 두 번 이상 들어가지 않는다.
- 독립 검증 통과는 여전히 0이다. 이 결과는 수익성 증거가 아니다.

## 테스트
- 새 테스트 16개(`test_selection_stopfill_20261022.py`): 청산만 다른 변형은 같은 진입 키, 진입이 다르면 다른 키,
  변형은 배치에서 빠지고 RESEARCH_ONLY 유지, 다음 배치에서도 빠짐, 최상위 후보 유지, 잘못된 설정 거부, 롱·숏 봉 극단가
  체결, 갭은 시가, 익절 불변, 무작위 300회에서 봉 극단가 체결이 손절가 체결보다 좋지 않음, 설정 파일 고정·코드 해시 포함.
- 기존 `test_pipeline.py`의 3개 테스트는 두 번째 진짜 후보로 "EDGE의 horizon만 바꾼 변형"을 썼다. 이제 그 변형은
  규칙상 배치에 들어가지 않으므로, 진입이 다른 후보(`hour_spec(0, 3)`)로 바꿨다. 테스트가 보려는 것(배치 순서·알파
  지출·잠금 캠페인 예산)은 그대로다.

## 하지 않은 것
- 통계 기준, 비용 가정 파일, 사전등록 초안은 바꾸지 않았다. 검증 창·잠금 창·IW1은 열지 않았다.
- 손절 미끄러짐을 줄이는 방향(예: 손절가 체결)으로 기본값을 되돌리려면 새 버전 파일과 ADR이 필요하다.
