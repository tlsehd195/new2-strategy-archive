# ADR 0082 — research-ci 작업 시간 제한을 30분에서 60분으로 올린다

- 상태: Accepted
- 날짜: 2026-11-16
- 요청: 동동, 2026-11-16 "너의 추천으로 진행해"
- 관련: ADR 0067(CI 전체 run 스크립트 검사), ADR 0081
- 시작 커밋: `a441ba7` (main, PR #81 병합). ADR 0078/0079는 열린 PR #79가 쓰고 있어 0082를 쓴다.

## 1. 문제

`research-ci`의 `test` 작업(Python 3.11, 3.13 매트릭스)은 단위 테스트가 늘면서 전체 스위트에 약 23~35분이 걸린다. `timeout-minutes: 30`에 걸려 3.13 작업이 취소된 적이 있다(PR #81 병합 때, main 최신 커밋의 실행도 같은 이유로 취소). 취소는 테스트 실패가 아니라 시간 초과이므로 병합 판단에 쓸 수 있는 신호가 없다.

## 2. 결정

- `.github/workflows/research-ci.yml`의 `timeout-minutes`를 30에서 60으로 올린다.
- 코드, 테스트 단언, 단계 구성은 바꾸지 않는다. 다른 워크플로(`fetch-data.yml`, 120분)는 그대로 둔다.
- 60분은 현재 최대 소요(약 35분)의 1.7배다. 멈춘 작업은 여전히 1시간 안에 끝난다.

## 3. 제안만 하고 이번에는 하지 않는 것

- 느린 테스트를 `unittest` 병렬 실행(예: 분할 후 별도 작업)으로 나눠 소요 시간을 줄이는 것.
- 먼저 느린 테스트 상위 N개를 `--durations`로 측정한 뒤 정한다.
