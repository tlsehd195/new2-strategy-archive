# ADR 0004 — 자동 전략 진화, 단계별 검증, 잠금 창 캠페인, 논문 적용·보류

- 상태: Proposed (PR #3, 머지 시 Accepted)
- 날짜: 2026-10-15
- 범위: `run/discovery/{strategy_spec,evolution,search,stats_mc,pipeline,campaigns,paper,autoloop,data_fetch}.py`, `config/promotion_v1.json`, `runner.py --mode`, `run_cycle.sh`
- 선행: [ADR 0003](0003-core-defects-data-defaults-lookahead-ledger.md)

## 맥락
기존 엔진은 고정된 7개 계열 격자(779개 후보)를 한 세대로 미리 등록하고, 그 세대 전체에 BH-FDR을 적용했다. 이번 지시는 다음을 요구했다.
- 자동 생성, 변형, 결합, 계보 추적
- 반복·적응형 탐색에서도 유효한 다중검정
- 잠금 TEST의 그룹 단위 통제
- 단계별 자동 승격과 격리된 페이퍼 실행

적응형 탐색에서는 앞선 결과를 보고 다음 가설을 고르므로 "세대마다 BH"는 오류율을 보장하지 못한다.

## 결정
1. **선언형 명세** `strategy_spec_v1`
   - 지표 레지스트리(플러그인 훅 `register_feature`) 위의 조건 AND/OR와 필터로 구성한다. 청산은 보유기간과 선택적 손절·익절, 리스크 블록은 범위가 고정되어 있다.
   - 정규화 단계에서 범위, 모순 조건, 복잡도 상한(진입 3, 필터 2, 합계 4)을 검사하고 기본값을 채워 넣는다. 순서와 중복은 정규화로 제거되며, ID는 정규화된 정의의 해시다.
   - 7개 기존 계열은 `legacy_to_spec`로 같은 신호가 나는 명세로 변환해 탐색의 씨앗으로 쓴다. 신호 동일성은 테스트로 확인했다.
   - 손절·익절은 보수적으로 체결한다. 같은 봉에서 둘 다 닿으면 손절로 보고, 갭은 시가로 체결한다.
2. **변형과 계보**
   - 13개 타입 연산자와 교배를 둔다. 연산자는 파라미터, 임계값, 보유기간, 청산, 조건 추가·삭제·교체, 방향, 논리, 리스크, 심볼 분리를 다룬다.
   - `specs.jsonl`은 정의를 한 번만 기록하고, `lineage.jsonl`은 생성 경로마다 한 줄을 남긴다. 한 줄에는 부모, 연산자, diff, 생성기 버전, 시드, 컨텍스트, 정책·예산, 부모의 DEV 스냅샷이 들어간다.
   - 같은 자식이 다른 부모에서 다시 나오면 전략 하나에 계보 두 줄로 기록된다. 실패한 자식도 지우지 않는다.
3. **탐색은 DEV만 본다** (`search.py`)
   - `dev_feedback`은 stage=dev 기록의 화이트리스트 키만 반환하고, 다른 단계 기록이 들어오면 `FeedbackLeak`을 낸다.
   - 순위는 DEV 목표(상한을 둔 t, 폴드 안정성, MDD, 비용 비중, 복잡도)의 파레토 정렬과 계열별 니치 상한으로 정한다.
   - 탐색 비율, 교배 비율, 라운드·총량·무효비율·인내 예산이 있다. 라운드 시드는 `(seed, round)`에서 유도하므로 중단 후 재개해도 같은 자식이 나온다(테스트 확인).
4. **단계 분리와 다중검정** (`pipeline.py`)
   - DEV 결과는 검정이 아니라 선별 신호로만 쓴다.
   - 검증 구간은 **사전등록 배치** 단위로 다룬다. 구성원, α, 방법, 시드를 먼저 기록한 뒤 평가하며, 중단된 배치는 새로 만들지 않고 이어서 완료한다.
   - 배치 안에서는 심볼별로 Romano–Wolf studentized StepM을 쓴다. 전략 간 임의 의존에서도 강한 FWER를 통제한다.
   - 같은 검증 창의 k번째 배치에는 `α_k = α·6/π²/k²`를 배정한다. 합계가 α 이하이므로, 나중 배치를 앞의 DEV 결과를 보고 골라도 합집합 경계가 성립한다.
   - SPA(Hansen), Reality Check(White), HAC p에 대한 BH/BY는 진단값으로만 기록한다.
   - 기존 세대 BH 경로는 그대로 유지한다.
5. **강건성 필터**는 순위에 쓰지 않는다. 항목은 다음과 같다.
   - 비용 1.5배와 2배 시나리오
   - 변동성×추세 4개 레짐
   - 검증 MDD
   - 상위 5% 이벤트·최대 일자 집중도
   - DEV 이웃 파라미터
   - DEV 폴드와 검증 절반을 이은 walk-forward
   - 표본 수
   - 탐색 전체 DEV 일수익 행렬의 PBO/CSCV(S=16)
   - 정상 부트스트랩 CI(기록만 함)

   PBO를 계산할 수 없으면 통과로 치지 않고 `BLOCKED_STATISTICS`로 둔다.
6. **잠금 창 캠페인** (`campaigns.py`)
   - 잠금 데이터를 읽기 전에 최종 구성원과 α를 기록한다.
   - 창별 c번째 캠페인에 `α_c = α·6/π²/c²`를 주고, 캠페인 안에서는 Bonferroni(`α_c/m_c`)를 적용한다.
   - 창당 캠페인은 3회까지이고, 그다음에는 `WINDOW_RETIRED`로 막는다. 노출 전에 데이터가 없어 중단된 캠페인은 횟수에 넣지 않는다.
   - 기존 세대 경로에서는 BH 결정 하나의 잠금 진입자를 캠페인 하나로 묶는다. 같은 원장을 쓰므로 두 경로의 사용 횟수가 합산된다.
   - 전략×심볼 단일 사용 레지스트리는 그대로 유지한다.
7. **상태와 승격**
   - 상태는 (전략, 컨텍스트)별 append-only로 기록하고 전이표를 강제한다. 상태는 `RESEARCH_ONLY`, `VALIDATION_SURVIVOR`, `PAPER_TEST_READY`, `REJECTED`, `INCONCLUSIVE`, `BLOCKED_DATA`, `BLOCKED_COST`, `BLOCKED_STATISTICS`다. 차단 상태는 `resume_to`로만 복귀한다.
   - 승격 심사는 dev, validation, robustness, locked 기록 ID를 증거로 연결한다. 하나라도 없으면 승격하지 않는다.
   - 비용 모델이 미검증이면 `UNVERIFIED_COST_MODEL` 라벨을 붙인다. 설정으로 이를 금지하면 `BLOCKED_COST`가 된다.
   - 승격 기준은 `config/promotion_v1.json`에 있고, 파일 해시가 컨텍스트에 들어간다.
8. **페이퍼 = 격리 리플레이**
   - 잠금 창 이후의 저장 데이터로만 1회 재생한다. 네트워크, 주문 API, 거래소 클라이언트가 없음을 소스 검사로 확인했다.
   - 결과는 증거와 실패 기억으로만 남기고, 탐색 순위에는 쓰지 않는다.
9. **자동 루프와 데이터 확보**
   - `runner.py --mode legacy|evolve|full`과 `NEW2_DISC_MODE`를 둔다. 사용할 데이터가 없으면 `CYCLE_BLOCKED_DATA`로 종료 코드 4를 낸다.
   - `data_fetch.py`는 명시적으로 허용할 때만 네트워크를 쓴다. 임시 파일, CHECKSUM, 안전한 압축 해제, 품질 게이트, 원자적 rename, 출처 기록 순서로 동작하며 기존 파일은 덮어쓰지 않는다.

## 논문 적용·보류 (원문·수식을 확인한 것만 적용)
| 논문 | 판단 | 근거·차이 |
|---|---|---|
| White (2000) Reality Check | 적용(진단) | V=max√n·f̄, 정상 부트스트랩, 최소유리 귀무가설. 일별 순수익률 사용. |
| Hansen (2005) SPA | 적용(진단) | 표준화 T, g_l/g_c/g_u, κ(n,i) 분산. 정상성·α-mixing 가정은 15분 암호화폐에서 **가정**으로 명시함. |
| Romano & Wolf (2005) StepM | 적용(검증 게이트) | Algorithm 4.1 studentized. σ는 Hansen 분산으로 고정(일관 선택). |
| Politis & Romano (1994) | 적용 | 기하 블록(평균 1/q), 원형 인덱스. q=n^(-1/3)은 선택값이며 기록함. |
| Benjamini & Hochberg (1995) | 유지 | 기존 세대 경로. PRDS 가정은 미검증이라 BY를 함께 기록. |
| Benjamini & Yekutieli (2001) | 적용(진단) | Thm 1.3: q/Σ1/i, 임의 의존. |
| Bailey et al. (2017) PBO/CSCV | 적용(게이트) | 기존 `pbo_cscv`가 원문과 일치함을 확인(ω̄=rank/(N+1), logit≤0 비율). |
| Foster & Stine (2008) α-investing | 검토 후 보류 | p-값의 조건부 타당성이 필요한데 같은 창을 재사용하므로 부적합. 1/k² 지출로 대체. |
| Newey & West (1987) | 기존 유지 | 기존 Bartlett HAC 구현. 이번 작업에서 원문 재대조는 하지 않음. |
| Bailey & López de Prado (2014) DSR | 적용(진단, 게이트 아님) | 1차 원문은 읽지 못했다. 독립된 두 구현이 인용한 수식(SE에 왜도·첨도 반영, E[max SR]=√V·[(1−γ)Φ⁻¹(1−1/N)+γΦ⁻¹(1−1/(Ne))])을 교차 확인해 기존 `deflated_sharpe`와 일치시킴. 시도 수 N·분산 V는 컨텍스트 전체 DEV 시도에서 계산. 출처 한계 때문에 통과 기준에 쓰지 않고 `robustness.checks.dsr`에 기록만 함. |
| Hansen–Lunde–Nason (2011) MCS T_max | 적용(진단) | CREATES 워킹페이퍼 본문의 알고리즘 확인: t_i.=d̄_i./√var, 최대 t 제거, p값의 누적 최댓값. **차이**: 원문은 이동블록 부트스트랩, 여기는 정상 부트스트랩이고 분산은 부트스트랩 분산(원문 부록 추정량은 미확인). 순위로 쓰지 않고 배치의 `mcs` 집합만 기록. |
| Hsu–Hsu–Kuan (2010) Step-SPA | 보류 | 초록만 확인(SPA의 단계적 확장). 본문 없음. StepM이 단계적 통제를 이미 제공. |
| Sullivan–Timmermann–White, Diebold–Mariano, Giacomini–White | 보류 | 원문 미확인. StepM이 "구분 불가 후보 억지 순위화 금지" 역할을 부분적으로 맡음(기각 집합만 통과, 순위 없음). |
| GA/GP 계열(Allen–Karjalainen, Dempster–Jones, Long 외 2026 등) | 미적용 | 원문 미확인. 변형 연산자와 파레토 탐색은 일반 공학 설계이며, 논문 방법을 구현했다고 주장하지 않음. |
| 암호화폐 기술적 분석·장중 수익률·미시구조 논문(8, 9, 24–31, 42–46) | 보류 | 원문 미확인. 지표 레지스트리에 개별 효과를 추가하지 않음. |
| 강화학습·딥러닝·가격 예측(47–61) | 보류 | 사용자 우선순위상 마지막 단계. 구현하지 않음. |

## 결과
- 테스트를 추가했다(명세·연산자·저장소·통계 19개, 파이프라인 23개, 기존 경로 캠페인 2개, 데이터 수집 5개). 합성 세계에서 다음을 확인했다.
  - 실제 효과가 있는 전략은 증거가 연결된 채 `PAPER_TEST_READY`까지 간다.
  - 귀무 세계에서는 아무것도 승격되지 않는다.
  - 검증 구간에만 효과가 없는 경우 DEV 승자가 탈락한다.
  - 귀무 상황의 RC/SPA/StepM 거짓 양성률이 상한 이내다.
- 실데이터 사이클은 `CYCLE_BLOCKED_DATA`(종료 코드 4)였다. 데이터 디렉터리가 없고 data.binance.vision 접근이 프록시 403으로 막혀 있어 실데이터 검증은 하지 않았다. 수익성은 `NOT_VALIDATED`다.
- 기존 세대 경로의 잠금 PASS는 이제 캠페인 member α도 충족해야 한다. 기준을 더 엄격하게 한 변경이다.
- 남은 위험은 다음과 같다.
  - 특징 계산이 O(n·window)라 긴 창은 느리다(입력 단위 캐시로 완화).
  - 일별 집계와 정상성 가정의 적합성은 실데이터로 확인되지 않았다.
  - 비용 모델이 미검증이다.
  - 메인 NEW2와 통합하지 않았다.
