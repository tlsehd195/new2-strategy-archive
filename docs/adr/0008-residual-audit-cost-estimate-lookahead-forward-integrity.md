# ADR 0008 — 잔여 감사(2026-10-17): 공개 시세 추정 강화, 비용 계산 시점 누출 제거, 체결 증거 규칙, 전진 페이퍼 무결성

- 상태: Proposed (이 PR, 머지 시 Accepted)
- 날짜: 2026-10-17
- 범위: `run/discovery/public_cost_estimate.py`, `public_market_collect.py`, `config/cost_public_estimate_v2.json`(신규), `cost_calibration.py`, `evaluator.py`, `execution_sim.py`, `portfolio.py`, `paper_forward.py`, `ops.py`, `store.py`, 사용하지 않는 import 정리(`engine_lib.py`, `evolution.py`, `generator.py`, `handoff.py`, `runner.py`, 테스트 4개), `tests/test_residual_20261017.py`(신규), `tests/test_public_estimate.py`, `tests/test_residual_fixes.py`, `.github/workflows/research-ci.yml`, `docs/공개시세_비용추정_로컬실행_안내.md`, `run/discovery/README.md`
- 선행: [ADR 0006](0006-cost-verification-forward-paper-data-manifest-ops-ci.md), [ADR 0007](0007-assumed-cost-profile.md)

## 맥락
PR #4~#7이 모두 main에 병합된 상태(`c39578f`)에서 잔여 감사를 했다. 사용자는 PC에서 공개 호가를 수집하는 중이고, 이 작업은 수집을 실행하지 않는다. 수집 데이터로 추정을 돌린 적은 아직 없다. 감사에서 확인한 결함은 다음과 같다.

1. **비용 계산의 시점 누출**: 연구 평가기(`evaluator.run_event_study`)는 t+1 시가에 진입하면서 참여율과 비용을 진입 봉(t+1) 자신의 거래대금으로 계산했다. 청산도 청산 봉의 거래대금을 썼다. 주문을 보내는 시점에는 그 봉의 거래대금을 알 수 없다. 거래대금이 큰 봉 직전에 신호가 나는 전략은 비용이 낮게 잡히고, 참여 상한 거부도 미래 정보로 결정됐다. `execution_sim.fill_fraction`(진입 봉)과 `portfolio.simulate_portfolio`(진입·청산 봉, 그리고 진입 봉 종가까지 쓰는 변동성 기반 포지션 크기)도 같았다. 공개 시세 추정기는 처음부터 "직전 마감 15분봉"을 기준으로 충격 계수를 적합하므로, 엔진과 추정기의 기준 봉도 서로 달랐다.
2. **공개 시세 추정기(v1)의 비보수성**:
   - 매수·매도 걷기 비용을 평균했다. 엔진은 양쪽에 같은 비용을 물리므로 비싼 쪽을 써야 보수적이다.
   - 50단계 호가로 주문을 다 채우지 못한 스냅샷은 조용히 빠졌다. 얇은 호가(비용이 가장 큰 경우)만 골라 버리는 셈이라 충격 계수가 낮게 편향된다.
   - NaN·무한대 가격이 `p <= 0` 검사를 통과했다. 시각이 없는 줄은 정렬에서 `KeyError`가 났다. 같은 시각 중복, 다른 종목 폴더에 쓰인 줄, 오래된 호가나 15분봉을 거르지 않았다.
   - `collect_manifest.json`의 해시를 확인하지 않았다. 앞선 업로드에서 실제로 전송 손상이 있었다(`.notes/inputs.md`).
   - 추정 기록을 원본으로 다시 검증하는 기능이 없었다.
3. **비용 검증(`cost_calibration`)의 증거 규칙**:
   - 공개 호가나 가상 주문(`quote_snapshots`, `paper_fill_monitor`) 행에 체결가·수수료를 적어 넣을 수 있었다.
   - 체결률·거부율을 호가 스냅샷과 가상 주문까지 포함한 전체로 나눴다. 그래서 거부율이 희석됐다.
   - 검증 범위(`scope`)의 종목에 체결이 1건뿐인 종목도 들어갔다. 명목금액 범위도 가상 호가(1달러)까지 포함했다.
   - 같은 보고서 줄이 두 번 들어가도 받아들였다. NaN 거래대금은 충격 계수를 0으로 만들었다.
   - `check_record`는 사유가 적힌 VERIFIED 기록을 해시만 맞으면 통과시켰다.
4. **전진 페이퍼**:
   - 평가할 때 계획에 등록된 체결 규칙이 아니라 현재 설정 파일의 규칙을 썼다.
   - 비용 모델이나 전략 정의가 등록 뒤에 바뀌어도 감지하지 못했다.
   - 봉 기록을 덧붙인 뒤 상태를 저장하기 전에 프로세스가 죽으면, 재개할 때 같은 봉을 다시 덧붙였다(중복 봉 → 잘못된 평가).
   - 결론을 기록한 뒤 상태 저장 전에 죽으면, 결론 평가 기록이 두 번 남았다.
   - 손절·익절로 청산 봉 안에서 나간 거래는 그 봉의 최악 가격으로 청산(강제 청산) 여부를 확인하지 않았다(낙관적).
5. **운영**: `ops.py loop`는 PARTIAL_FAILURE(runner 종료 코드 2) 사이클이 있어도 횟수를 다 채우면 0으로 끝났다.

## 결정
1. **기준 봉 통일**: 진입·청산의 비용, 참여 상한 판단, 체결 비율, 포지션 크기 변동성은 모두 **체결 직전에 마감된 봉**(진입은 결정 봉 t, 청산은 exit-1)으로 계산한다. 추정기의 충격 적합 기준(직전 마감 15분봉 거래대금)과 같다. 버전 태그를 올렸다: `exec-sim-v2`, `portfolio-mtm-v3`. 코드 해시가 바뀌므로 실험 컨텍스트 ID가 새로 생기고, 이전 컨텍스트의 결과는 재사용하지 않는다.
2. **공개 시세 추정 기준 v2** (`config/cost_public_estimate_v2.json`): 수집 데이터로 추정을 한 번도 돌리지 않은 상태에서 고정했다. v1의 기준값은 그대로 두고 추정기만 더 엄격하게 했다.
   - 스냅샷마다 매수·매도 중 비싼 쪽을 쓴다(`side_aggregation: "max"`).
   - 얇은 호가 비율이 1%(`max_thin_share`)를 넘는 주문 크기는 충격 적합에서 **통째로** 뺀다. 그 크기에서 깊은 호가 스냅샷만 남기면 하향 편향이 생기기 때문이다. 적합에 쓸 크기가 하나도 남지 않으면 `INSUFFICIENT_PUBLIC_DATA`다. 기록에는 `unsupported_notionals`, `supported_max_notional`, `fit_participation_range`를 남긴다.
   - 무효 처리: 비유한 수치, 호가 시각 없음, 5초보다 오래된 호가, 17분보다 오래되었거나 아직 마감되지 않은 15분봉, 같은 시각 중복, 폴더와 다른 종목. 모두 개수를 세며, 무효 비율 1% 기준은 v1과 같다.
   - `collect_manifest.json`이 필수다. 목록에 없는 파일, 해시가 다른 파일, 목록에는 있는데 없는 파일이 하나라도 있으면 `INSUFFICIENT_PUBLIC_DATA`다. 창을 닫아 매니페스트를 쓰지 못한 경우를 위해 수집기에 `--manifest-only`(네트워크 없음)를 추가했다.
   - `check_estimate`는 사유가 남은 기록, v2가 아닌 기준, 사용 불가 종목, 관측했다고 표시된 수수료, 비용 모델이 아닌 매개변수를 거부한다.
   - `verify_estimate` / `--verify`: 원본 파일 해시를 다시 확인하고, 기록에 담긴 기준으로 추정을 다시 계산해 상태와 매개변수가 같은지 비교한다. 수집 데이터 없이도 오프라인으로 돌아간다.
   - v1 기준 파일은 이력으로 남기고, 불러오면 "superseded"로 거부한다.
3. **체결 증거 규칙** (`cost-calib-v2`):
   - `exchange_fills`가 아닌 행은 체결가·체결 금액·수수료를 가질 수 없다.
   - 같은 줄이 중복되거나 수치가 비유한이면 거부한다. 시각·종목·주문 유형도 검사한다.
   - 체결률은 실제 주문(`exchange_fills`)으로만 계산한다.
   - 검증 범위는 검증 구간 체결이 기준(200건) 이상인 종목과, 그 체결들의 명목금액 범위다.
   - `check_record`는 사유가 있거나 범위가 비어 있는 VERIFIED 기록을 거부한다.
4. **전진 페이퍼**:
   - 평가는 계획에 등록된 체결 규칙과 비용 참여 상한만 쓴다.
   - 단계마다 계획 무결성(계획 ID, 전략 정의 해시, 비용 identity, 체결 규칙 버전, 컨텍스트)을 확인한다. 다르면 `PLAN_CONTEXT_CHANGED`로 `PAPER_ERROR`가 되고, 평가하지 않는다.
   - 해시 체인 봉 기록을 기준으로 상태를 복구한다(`recovered`에 기록). 결론은 같은 계획에 대해 한 번만 기록한다.
   - 봉 안에서 청산한 거래는 청산 봉의 최악 가격까지 강제 청산을 확인한다.
5. **운영**: `ops.py loop`는 횟수를 채워도 PARTIAL 사이클이 하나라도 있으면 종료 코드 2를 낸다(`partial_cycles` 기록).
6. **CI**: 사용하지 않는 import 17개와 변수 1개를 정리했다. 그래서 pyflakes 전체 규칙(F)을 게이트로 바꿨다. v1 진단 파일 `portfolio_sim.py`, `funding_cost.py`는 제외한다.

## 바꾸지 않은 것
- 통계 기준(`promotion_v2.json`, StepM·α 소비, PBO 0.5, DSR 비게이트), 비용 검증 기준(`cost_verification_v1.json`), 페이퍼 기준(`paper_forward_v1.json`), 가정 비용 프로필 값은 바꾸지 않았다.
- StepM·SPA·Reality Check·Step-SPA·MCS·BH/BY·PBO(CSCV)·DSR·MinBTL의 식과 호출 경로를 다시 읽었다. 결함은 찾지 못했다. 근거는 감사 보고서 §4에 있다.
- 검증 생존자가 없으면 잠금 TEST는 열리지 않는다(기존 동작, 확인함).
- **결정 완료(2026-10-17, [ADR 0009](0009-locked-test-requires-verified-cost.md))**: 사용자가 "닫아 두기"를 골랐다. 아래는 결정 전 상황이다. 결정 전에는 비용이 미검증(ASSUMED/ESTIMATED/UNVERIFIED)이어도 검증 생존자가 생기면 잠금 TEST를 연다. 결과는 승격 심사에서 `BLOCKED_COST`가 된다. 잠금 창은 전략·종목당 한 번만 쓸 수 있으므로, 나중에 비용이 VERIFIED가 되어도 그 전략은 잠금 TEST를 다시 받을 수 없다. "비용 미검증이면 잠금 TEST를 열지 않고 창을 보존한다"로 바꿀지는 사용자 결정으로 남겼다. 실데이터에서 생존자는 지금까지 0명이라 아직 쓰인 창은 없다.

## 결과
- 실데이터 사이클(새 코드, 기본 비용 프로필)과 테스트 결과는 `run/audit/AUDIT_RESIDUAL_20261017.md`에 있다.
- 남은 위험:
  - 공개 호가는 체결이 아니다. 숨은 물량, 대기열, 역선택은 근사일 뿐이다.
  - 50단계 호가 밖의 깊이는 볼 수 없다. 그래서 100만 USDT 같은 큰 주문은 적합에서 빠질 수 있다.
  - 엔진 주문(1만 USDT)의 참여율은 적합 범위보다 작다. 따라서 충격은 √ 모형의 외삽이다.
  - PID 파일 잠금은 PID 재사용 시 살아 있는 소유자로 오인할 수 있다. 이 경우 실행이 멈추는 쪽으로 실패하고, 겹쳐 실행되지는 않는다.
