# ADR 0061 — 신규 상장 숏 가설: 전향 자료 수집기와 전향 전용 사전등록 초안

- 상태: Accepted (도구·초안만)
- 날짜: 2026-11-02
- 사용자 요청: 동동, 2026-11-02 "새 상장 숏 가설 진행"
- 범위: `run/discovery/newlisting_collect.py`(수집기), `run/discovery/tests/test_newlisting_collect.py`, `run/audit/evidence_strong_hypotheses_20261102/prereg_newlisting_short_forward_v2_DRAFT.json`, 같은 폴더의 `NEWLISTING_COLLECT_HOWTO.md`.
- 열지 않은 것: 검증·잠금·IW1·종이 구간. 사전등록 활성화 없음. DEV 재시험 없음. 기준·엔진·비용 모델 변경 없음. 수집기는 클라우드에서 실행하지 않았다(바이낸스 접속 불가, 단위 시험은 가짜 거래소로만).

## 맥락
ADR 0060에서 신규 상장 30일 숏은 중앙값이 크게 이기지만 이벤트의 10~17%가 진입가의 2배 이상 폭등해 탈락했다. 손절·비중 상한은 결과를 본 뒤 만든 규칙이라 같은 DEV에서 증거가 될 수 없고, 앞으로 쌓이는 새 상장에서만 시험할 수 있다. 그러려면 상장 시점의 호가·체결·펀딩을 지금부터 기록해야 한다. 이벤트는 월 약 7~10건이라 30건까지 4~5개월이 걸린다.

## 결정
- 공개 키 없는 엔드포인트만 쓰는 수집기를 추가: 첫 실행 때 기존 종목을 baseline으로 저장, 이후 새 USDT 무기한 종목을 신규 상장으로 감지해 원본 exchangeInfo(상장일 포함)와 감지 시각을 기록하고 30일간 호가 50단·마크가·펀딩·1분봉·전체 체결을 저장. 실패는 실패로 기록하고 값을 만들어 넣지 않는다. 실행 시간 상한 720시간, 재개 가능, SHA-256 매니페스트.
- 전향 전용 사전등록 초안(`H_LIST_v2_forward`, 시도 1, 이벤트 30건 이상, 월 군집 t ≥ 2.0 등)을 DRAFT_FORWARD_ONLY_NOT_ACTIVE로 저장. 이 규칙이 DEV 결과 이후에 만들어졌다는 점을 초안에 명시.
- 실행 위치는 Oracle VM 또는 PC. 배치·업로드 절차는 HOWTO에.

## 한계
- 이 환경에서는 실제 바이낸스 응답으로 확인하지 못했다(필드명과 `onboardDate`는 공개 문서·ADR 0060 기준). 첫 짧은 실행으로 확인 필요.
- 신규 상장 감지는 60초 주기라 상장 직후 몇 분은 비고, 지연이 기록된다.
- 시장 자료일 뿐 체결 기록이 아니어서 비용을 VERIFIED로 만들지 못한다.

## 청산 수집분 업로드 확인 (사실 기록)
- 이 저장소의 `data/liquidations.db`는 2026-10-13~14의 1.7일(OKX 4,838·Bybit 223건)에서 멈춘 옛 샌드박스 백업이며, 그 뒤 Oracle VM의 청산 수집분(NEW2 ADR-0085, 로컬 `var/data/liquidations/*.jsonl`)은 저장소·프로젝트 파일 어디에도 없다. 호가 수집분(10-16~19, 10-23~27, 알트 96시간)은 업로드됐으나 청산은 아니다. 클라우드는 VM에 접속할 수 없다.
