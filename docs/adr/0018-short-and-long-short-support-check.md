# ADR 0018 — 숏·롱숏 지원 점검과 DEV 묶음 진단 도구

- 상태: Accepted
- 날짜: 2026-10-21
- 범위: 점검 + 새 읽기 전용 도구 `run/discovery/bundle_dev.py`(엔진·통계 기준 변경 없음)
- 선행: [ADR 0015](0015-dev-only-candidate-generation-r6.md), [ADR 0016](0016-independent-window-2020-market-cap-tranches.md)

## 맥락
"전략에 숏도 있고 롱+숏 조합도 만들 수 있는 것 아니었나?"라는 질문에 코드를 읽고 R6을 똑같이 재현(컨텍스트 `C2-f64e792160a0222650f2`, 894개 평가, 64개 DEV 통과)해 확인했다. DEV 구간만 사용했고 IW1, 검증, 잠금 TEST는 열지 않았다.

## 점검 결과
- 지원됨: 전략 정의의 `direction`은 long / short / symmetric(조건이 반대로 서면 숏). 평가기는 방향에 따라 손익, 비용, 펀딩(`side * rate`)을 계산하고 포트폴리오 시뮬레이터도 숏 청산 가격을 따로 다룬다. 시드 705개 중 숏 계열이 405개(flow_z 360, fund_z 45) 외에 fng/tod 숏이 있다.
- 정정: DEV 통과 64개는 롱 56, 숏 3, 양방향 5다. "롱 돌파형뿐"은 IW1용 앞쪽 20개만 본 설명이었다.
- 숏이 적은 이유: 숏 501개 평가에서 평균 순수익 중앙값이 -16bp(롱 -6bp). 2021~2024 DEV는 상승 구간이 많다. 숏 148개는 극단 임계값 때문에 거래 8~15건이라 `dev_underpowered`로 보류(t=37 같은 값은 12건짜리라 신뢰 불가). 통계·비용 기준은 완화하지 않았다.
- 없는 기능: (a) 한 전략 안에서 롱 규칙과 숏 규칙을 따로 쓰기, (b) 통과 전략을 롱+숏으로 묶어 평가하기, (c) 한 코인 롱·다른 코인 숏 짝 전략.

## 결정
사용자가 (b)만 추가하기로 했다. `bundle_dev.py`는 한 컨텍스트의 DEV 통과 전략의 DEV 일별 시계열을 동일 가중으로 묶어(롱, 숏, 양방향, 롱+숏, 롱50/숏50) 일평균, 연환산 샤프, 최대 낙폭, 롱·숏 상관을 낸다. 원장에 쓰지 않고 판정에 쓰지 않는다. (a), (c)는 스펙·지문·진화 연산을 건드리는 큰 변경이라 하지 않았다.

## R6 DEV 결과(`run/audit/evidence_direction_20261021/bundle_dev_r6.json`)
| 묶음 | 일평균 bp | 연환산 샤프 | 최대 낙폭 bp |
|---|---|---|---|
| 롱 56 | 5.7 | 1.30 | 3030 |
| 롱+숏(3) 동일가중 | 5.7 | 1.39 | 2914 |
| 롱50/숏50 | 6.0 | 1.69 | 2391 |
| 숏 3 | 6.3 | 1.03 | 6144 |
롱·숏 상관 -0.12. 숏 구간이 낙폭을 줄이는 방향이지만, 숏은 3개뿐이고 모두 같은 `taker_share_z>3` 계열이며 이 숫자는 같은 DEV 일자로 고른 후보라 선택 편향이 있다. 승격 근거가 아니다.

## 한계
- 새 독립 구간이 없으므로 이 묶음을 검증하지 않는다. IW1은 닫힌 채로 둔다.
- 묶음 조합을 많이 시도하면 우연히 좋아 보이는 조합이 늘어난다. 도구는 사전 정해진 묶음 5개만 낸다.
