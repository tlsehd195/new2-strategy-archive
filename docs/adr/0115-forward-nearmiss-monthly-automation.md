# ADR 0115 — CL1·FIP1·AF1 전진 모의 기록의 매달 자동 실행과 알림

- 상태: Accepted (운영 자동화만, 기준·규칙 변경 없음)
- 날짜: 2026-11-21
- 사용자 요청: 동동, 2026-11-21 "모의투자 CL1/FIP1/AF1이 되고 있는지, 오라클 VM에서 돌리는 것 아닌지" 확인 후 "ㅇㅇ"(매달 자동 실행·알림 설정 승인).
- 범위: GitHub Actions 워크플로 `.github/workflows/forward-nearmiss-monthly.yml` 한 개. `run/forward_nearmiss.py`, 사전등록, 통계 기준은 건드리지 않는다.

## 확인한 사실 (ADR 0112)
- 모의 기록은 오라클 VM·실시간 수집기·주문 어느 것도 쓰지 않는다. 2026-11-23부터의 성적을 바이낸스 월간 공개 아카이브로 사후 계산한다.
- 이전에는 자동 일정이 없었고, 매달 초 사람이 `fetch`와 `evaluate`를 돌려야 했다. 이 ADR이 그 부분을 자동화한다.

## 결정
- **일정**: 매달 3일 06:17 UTC에 실행하고, 5일에 한 번 더 시도한다(아카이브 게시 지연 대비). 이미 그 달 결과가 있으면 건너뛴다. 수동 실행(`workflow_dispatch`, 평가일 입력 가능)도 된다.
- **실행**: `forward_nearmiss.py fetch` → 마지막 완결 월의 일봉 파일이 100개 이상 있는지 확인 → `evaluate`. 마지막 달 자료가 아직 없으면 실패로 끝나고 계산하지 않는다(부분 자료로 계산하지 않음).
- **저장**: 결과 `forward_<월말>.json`은 main이 아니라 별도 브랜치 `forward-results`에 커밋한다. main 브랜치 보호와 충돌하지 않고, 코드 변경과 기록이 섞이지 않는다. 같은 달 파일이 이미 있으면 다시 쓰지 않는다.
- **알림**: 달마다 이슈 1개를 만들어 tlsehd195에게 배정한다(제목에 단계·일수). 실패하면 실패 이슈를 만든다.
- **안전**: 권한은 `contents: write`(forward-results 브랜치 푸시)와 `issues: write`뿐이다. 도구가 BTCUSDT·ETHUSDT와 검증·잠금·IW 구간을 읽지 않는 규칙은 그대로이고, 이 워크플로는 그 구간을 열지 않는다. 키·계정·주문 없음.
- 사전등록 커밋 시각 확인에 git 이력이 필요해 `fetch-depth: 0`으로 체크아웃한다. 내려받은 월간 파일은 변하지 않으므로 `actions/cache`로 재사용한다.

## 남은 위험
- 첫 실행은 2026-12-03이다. 워크플로 자체는 이 PR에서 한 번도 돌려 보지 않았다(클라우드에서 모의투자를 직접 돌리지 않는 규칙). 머지 후 `workflow_dispatch`로 한 번 수동 실행해 확인하길 권한다(11월에는 `asof`를 2026-12-03으로 두면 11-23~11-30 8일분으로 계산된다).
- GitHub Actions 결제 문제가 생기면 일정이 돌지 않는다. 그 경우 실패 이슈도 안 올 수 있으므로, 12-05까지 이슈가 없으면 Actions를 확인한다.
- 검정력이 낮다는 ADR 0112의 경고는 그대로다.
